ui/backend_probe.svelte.ts

Backend liveness probe — whether the app's backend is serving, read from its /health route.

AuthState.check_session can't tell a backend that's down from a logged-out caller, so a login gate probes /health to say the backend is needed instead of showing a login form that can't work. Only the health reply counts: a static server or an SPA fallback answering every path with a 200 HTML page is not a backend, and neither is a network error. Browser-safe — no server imports.

probe_backend
#

ui/backend_probe.svelte.ts view source

(options?: BackendProbeOptions | undefined): Promise<BackendProbeResult> import {probe_backend} from '@fuzdev/fuz_app/ui/backend_probe.svelte.js';

Probe whether the backend is serving: its health route must answer 2xx with a body that parses as HealthResponse. A timeout while the reply or its body is read reads as down — naming timeout_ms only when the default fetch timed out, since an injected fetch_health owns its own signal. A failure once the caller's signal aborted reports BACKEND_PROBE_ABORTED, not a timeout or a down backend. A body that isn't JSON is BACKEND_PROBE_NOT_HEALTH; any other failure reading it reports the error.

options?

the health fetch, the default fetch's timeout, and a signal to cancel it
