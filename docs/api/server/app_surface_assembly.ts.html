server/app_surface_assembly.ts

The route, middleware and surface assembly create_app_server shares with create_test_app_surface_spec (testing/stubs.ts).

One function decides the route order (consumer routes, then bootstrap, RPC endpoints, and the surface route), the middleware list (the transformed stack between the body limit and the post-route middleware), and the event specs (the audit stream's when the context carries one), so the stub surface the standard suites read can't drift from what the live server mounts. The callers build what differs — real or stub middleware handlers, live or stub bootstrap handlers, the server's own WS mount checks — and pass it in. Hono-free, so cross-process test consumers can import it.

(options: AssembleAppSurfaceOptions): AppSurfaceAssembly import {assemble_app_surface} from '@fuzdev/fuz_app/server/app_surface_assembly.js';

Assemble the routes, middleware list and surface of an app server.

Refuses an endpoint or bootstrap path outside the auth middleware's scope (assert_endpoint_in_auth_scope), a route that reads or mints a credential outside it (assert_credential_routes_in_auth_scope), and a transform_middleware that doesn't keep the stack mounted (assert_middleware_stack_mounted).

options

the context, the consumer's factories, and the built stack

type AssembleAppSurfaceOptions

returns

AppSurfaceAssembly

the route specs, transformed middleware, resolved endpoints, and surface

throws

  • Error - on any of the refusals above, or when `allowed_origins` is `null` and a WS endpoint declares no `allowed_origins`
