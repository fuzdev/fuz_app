AuditFactory
#

server/app_backend.ts view source

AuditFactory import type {AuditFactory} from '@fuzdev/fuz_app/server/app_backend.js';

Callback that builds the bound AuditEmitter after the backend's pool Db and Logger exist. The db it is handed is the backend's pool with the audit checkout bound (db_audit_checkout_timeout_ms, Db.with_checkout_timeout), so the emitter's pool writes wait longer than a request's checkout. Required on CreateAppBackendOptions so the consumer owns subscriber-chain composition and AuditLogConfig selection without the factory holding a default.

The factory is invoked exactly once during create_app_backend, after create_db resolves and migrations run. The emitter it returns lands on AppDeps.audit and is captured by every query/handler that reaches deps.audit.emit(...).

The canonical body is a one-liner over create_audit_emitter:

audit_factory: ({db, log}) => create_audit_emitter({ db, log, on_audit_event, audit_log_config, })

Returning an emitter built against a different db than the one passed in would route audit writes to a different pool than handlers query — the callback shape exists specifically to make that mistake structurally impossible.

(call)

type (params: { db: Db; log: Logger; }): AuditEmitter

params

type { db: Db; log: Logger; }
returns AuditEmitter

create_app_backend
#

server/app_backend.ts view source

(options: CreateAppBackendOptions): Promise<AppBackend> import {create_app_backend} from '@fuzdev/fuz_app/server/app_backend.js';

Initialize the backend: database + auth migrations + deps.

Calls create_db → ensure_read_committed, before anything writes → run_migrations (auth namespace, then any migration_namespaces from options in order) → audit_factory({db, log}) (db with the audit checkout bound) and bundles the result with the provided keyring and password deps and a connection_closer (empty until create_app_server adds its transports).

options

keyring, password deps, audit_factory, optional database URL, and optional migration_namespaces

type CreateAppBackendOptions

returns

Promise<AppBackend>

app backend with deps, database metadata, and combined migration results

throws

  • TransactionIsolationError - when the database's `default_transaction_isolation` is not `read committed`
  • MigrationError - `namespace-reserved` if a `migration_namespaces` entry bears a `reserved_migration_namespaces` name and is not the spine's own namespace

audit_factory

Build the bound AuditEmitter once the backend's pool Db + Logger exist. Required — the factory owns listener composition and AuditLogConfig selection without create_app_backend holding a default. Typical body:

connection_closer?

The closer to put on AppDeps.connection_closer. Omit for a fresh one — the usual case, since create_app_server adds the transports it mounts. Pass one built up front (create_realtime_closer()) when a transport is constructed before the backend and has to be added to the same closer the handlers will hold — e.g. an audit stream from create_audit_log_sse whose listener audit_factory registers.

type RealtimeCloser

migration_namespaces?

Additional migration namespaces to run after the builtin auth namespace. The shared schema_version table records one row per applied migration (namespace, name, sequence); order is append-only so forward-only guarantees hold per-namespace.

A name in reserved_migration_namespaces is rejected at startup (run_migrations refuses it before touching the database) unless the entry is the spine's own CELL_MIGRATION_NS / FACT_MIGRATION_NS object; auth always runs first, so it is never passed here. Omit for no extra namespaces. This is the only place to splice consumer migrations — DB init belongs to the backend lifecycle, not server assembly.

type readonly MigrationNamespace[]

db_checkout_timeout_ms?

Bound on the pool checkouts a request makes, in ms — the server env's FUZ_DB_CHECKOUT_TIMEOUT_MS. Default DEFAULT_DB_CHECKOUT_TIMEOUT_MS (5 s). A failed checkout answers 503 on every surface. Audit pool writes (failure rows) use db_audit_checkout_timeout_ms instead. A checkout that waits and then connects can take about twice the bound (db/db_pg.ts, "Checkout timeout"). Postgres only: PGlite and pglet have no pool, and a value passed with one is warned of at boot. Twin of the Rust BaseServerEnv::db_checkout_timeout.

type number

db_audit_checkout_timeout_ms?

Bound on the checkout behind each audit pool write, in ms — the server env's FUZ_DB_AUDIT_CHECKOUT_TIMEOUT_MS. Default DEFAULT_DB_AUDIT_CHECKOUT_TIMEOUT_MS (30 s). No response waits on a pool write; AppServer.close drains them within its own bound. Postgres only, like db_checkout_timeout_ms. Twin of the Rust BaseServerEnv::db_audit_checkout_timeout.

type number

ensure_read_committed

(db: Db): Promise<void> import {ensure_read_committed} from '@fuzdev/fuz_app/server/app_backend.js';

Refuse a database whose default_transaction_isolation is anything but REQUIRED_TRANSACTION_ISOLATION. Twin of the Rust ensure_read_committed.

One connection answers for all: every connection the pool opens has the same server, database, role and startup options (a URL's options, PGOPTIONS), and create_db adds no per-connection setting. It is read once, at boot; a setting changed while the server runs reaches new connections unchecked until the next restart.

REQUIRED_TRANSACTION_ISOLATION
#

server/app_backend.ts view source

"read committed" import {REQUIRED_TRANSACTION_ISOLATION} from '@fuzdev/fuz_app/server/app_backend.js';

The one default_transaction_isolation the server runs under. Twin of the Rust REQUIRED_TRANSACTION_ISOLATION.

The spine relies on READ COMMITTED: Db.transaction opens with a plain BEGIN, so transactions run at the database's default, and a read made after a lock (the migration chain's read after its advisory lock, a scope read after the scope lock, a last-admin count) sees what committed during the wait only under the fresh per-statement snapshot READ COMMITTED takes. read uncommitted is refused too, though Postgres runs it as READ COMMITTED: it names a level the spine does not run at, a Postgres-compatible engine might honor it, and refusing it costs nothing.
