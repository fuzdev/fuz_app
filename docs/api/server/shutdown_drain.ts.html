server/shutdown_drain.ts

The bounded wait AppServer.close makes for the work still in flight, and the report of what it gave up on.

Its own module, free of any server framework, so a process that serves the app (testing/cross_backend/testing_server_core.ts) reads the report without loading the server. Twin of the Rust spine's shutdown drain (fuz_http::serve_with_shutdown and its ServeShutdown).

(requests: Pick<RequestTracker, "drain_inflight" | "inflight_count">, audit: Pick<AuditEmitter, "drain_inflight" | "inflight_count">, upkeep: readonly Promise<...>[], timeout_ms: number, log: Logger): Promise<...> import {drain_effects_on_shutdown} from '@fuzdev/fuz_app/server/shutdown_drain.js';

Wait for the upkeep stops (the auth cleanup's pass in progress), then the requests held (HTTP requests, WS messages and WS upgrades still opening, one tracker — each until its handler has returned and its flush settled) and then the audit emitter's pool writes, until none is left or timeout_ms passes — then log an error naming what was given up on. One bound for all of it. Never rejects. The Rust shutdown joins its upkeep after the request drain; both wait concurrently against one deadline, so only the wait order differs.

ShutdownDrainGivenUp
#

server/shutdown_drain.ts view source

ShutdownDrainGivenUp import type {ShutdownDrainGivenUp} from '@fuzdev/fuz_app/server/shutdown_drain.js';

What AppServer.close gave up on at its drain bound (drain_effects_on_shutdown), each counted on its own: a request still waiting on its audit writes has those writes counted in audit_writes too, so the counts are not summed. Every count 0 is a shutdown that drained everything. Twin of the Rust spine's fuz_http::ServeShutdown.

requests

Requests still held — HTTP requests and WS messages alike, each with its handler or its effect flush still running, and WS upgrades still opening.

type number

type number

upkeep

Upkeep tasks still running — the auth cleanup pass in progress when auth_cleanup scheduled one. Twin of ServeShutdown's upkeep_given_up; here the pass is left to finish rather than aborted.

type number
