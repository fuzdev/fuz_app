http/json_text.ts

JSON text read as the Rust spine's serde_json reads it.

JSON.parse accepts three things serde_json refuses: an escaped lone surrogate ("\ud800", in a string or a key), a number out of f64 range (1e400, which JSON.parse reads as Infinity), and nesting 128 deep or more. Accepted, they don't survive storage: a lone surrogate is written to a text column as U+FFFD and refused by a jsonb one, and Infinity serializes as null. parse_json_text refuses all three, so a request body or frame gets the same verdict on both spines (invalid_json_body for a REST body, parse_error for a JSON-RPC body or frame, invalid_params for GET /rpc's params).

The check is one linear pass over the text after JSON.parse accepts it (is_serde_json_text): a few milliseconds a MiB, whatever the text holds.

"\u0000" is not refused here: both parsers accept it. Postgres refuses it, so the input steps do, as an invalid value rather than invalid JSON (scan_json_value in http/schema_helpers.ts).
