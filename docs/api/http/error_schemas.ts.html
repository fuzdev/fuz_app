http/error_schemas.ts

Standard error response schemas and error code constants for fuz_app routes.

Defines ERROR_* constants (single source of truth for machine-parseable error codes, which double as JSON-RPC data.reasons), the per-code REST error definitions (rest_error, one REST_* per code a route or middleware answers, each with its HTTP status and its body as a @fuzdev/fuz_schema schema), a type for error schema maps, and derive_route_errors, the definitions the framework answers a route with from its method, auth requirement, and input slots.

Used in RouteSpec.errors and MiddlewareSpec.errors, which each route's error map (http/route_errors.ts) unions with the derived definitions for the surface, the DEV error check, and the test helpers.

derive_route_errors
#

http/error_schemas.ts view source

({ method, auth, has_input, has_params, has_query, rate_limit }: DeriveRouteErrorsOptions): RestErrorDef<number, string, SchemaEntries>[] import {derive_route_errors} from '@fuzdev/fuz_app/http/error_schemas.js';

Derive the error definitions the framework answers a route with, from its method, auth requirement, input slots, and rate limit — each narrowed to what the route's own middleware can emit.

Route handlers declare additional definitions via RouteSpec.errors; the route's error map (resolve_route_error_map) is the union of these, the applying middleware's, and the route's own.

Derivation rules:

  • A body, an input other than null on a method other than GET: 400 invalid_request_body and invalid_json_body. A GET reads no body.
  • params: 400 invalid_route_params. query: 400 invalid_query_params.
  • auth.account === 'required' or auth.actor === 'required': 401 authentication_required — the pre-authorization gate's refusal when the credential isn't there. 'optional' does not derive 401.
  • auth.required_scope: 403 token_scope_required (carrying required_scope). auth.credential_types?.length: 403 credential_type_required (carrying required_credential_types). auth.roles?.length: 403 insufficient_permissions (carrying required_roles). In the order the gates fire; a route with more than one has each.
  • auth.actor !== 'none': 400 actor_required and actor_not_on_account, and 500 no_actors_on_account and account_vanished — what the dispatcher's authorization phase emits when it resolves an actor.
  • rate_limit: 429 rate_limit_exceeded (with retry_after).
  • POST: 415 unsupported_content_type (see is_post_content_type_refused in http/simple_request.ts).

ERROR_ACCOUNT_VANISHED
#

http/error_schemas.ts view source

"account_vanished" import {ERROR_ACCOUNT_VANISHED} from '@fuzdev/fuz_app/http/error_schemas.js';

Authentication validated an account, but a follow-up read in the authorization phase came back null — the account or its named actor row was deleted between the credential check and the dispatcher's build_request_context / build_account_context step. Torn read, not a missing-actor invariant violation. Surfaced as 500 so the operator sees the race signal; clients can retry. Distinct from ERROR_ACCOUNT_NOT_FOUND (stale token referencing a long-deleted account, raised at credential validation) and ERROR_NO_ACTORS_ON_ACCOUNT (the actor list enumerated empty).

A REST error definition: one code at one HTTP status, with the fields its body carries beside error. The status lives here and not on the ERROR_* constant, which is also a JSON-RPC data.reason with no fixed status.

The same code may have more than one definition, each a shape of its own (REST_AUTHENTICATION_REQUIRED and REST_AUTHENTICATION_REQUIRED_BOOTSTRAP).
