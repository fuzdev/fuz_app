http/request_target.ts

The strict readers of the request target: the query string to its pairs, and one path segment to its text — each percent-decoded, or refused.

An escape that doesn't decode is refused, never left literal and never replaced with U+FFFD: a % not followed by two hex digits is a malformed_escape, and decoded bytes that are not UTF-8 are invalid_utf8. A literal spelling would make %FF and %25FF one value, and a lossy one would make every invalid sequence the same U+FFFD — either way a handler reads a value the client never sent. The Rust spine's fuz_http::request_target reads by the same rule, and the shared table testing/cross_backend/request_target_conformance.json holds both to the same rows.

The pure readers take text and are Hono-free. read_request_query_pairs and read_request_route_params apply them to a request (a type-only import of the Hono context): every read of the query or the path params in the spine goes through one of the two.

read_query_pairs
#

http/request_target.ts view source

(query: string | null): QueryPairsRead import {read_query_pairs} from '@fuzdev/fuz_app/http/request_target.js';

Read a raw query string to its pairs, in order: split on & (an empty piece is no pair), each piece split at its first = (none reads an empty value), + read as a space, then name and value percent-decoded strictly. Every pair is read, a repeated key's and a nameless one's included, and the first component that doesn't decode refuses the whole string — a key no handler reads included, so no reader of one key sees a query another reader would refuse.

What a pair means is the caller's: query_first takes a key's first occurrence, and to_query_record builds the record a route's query schema parses.

read_request_route_params
#

http/request_target.ts view source

(c: Context<any, any, {}>): Result<{ readonly value: Record<string, string>; }, { readonly error: "malformed_escape" | "invalid_utf8"; }> import {read_request_route_params} from '@fuzdev/fuz_app/http/request_target.js';

Read the matched route's path params, every escape in the request path decoded strictly first — the one read of the path params in the spine.

The whole path is read rather than each param's own segments: the router matches the raw path (get_request_path), so a literal segment matches only as the template spells it — no escape at all — and on a matched route every escape is inside a param. Once every segment decodes, Hono's own reading of each param — the raw matched text by decodeURIComponent — is exactly its strict decoding, so the values are taken from Hono's match, which knows which segments each param spans.
