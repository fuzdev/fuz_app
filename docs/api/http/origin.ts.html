http/origin.ts

Request source verification middleware for API protection.

Verifies requests carry an Origin the server allows, or none. The origin check is one of three CSRF layers, beside SameSite: strict session cookies (auth/session_middleware.ts) and the JSON-only POST refusal (http/simple_request.ts): SameSite alone admits same-site pages, which include every other port on the same host, and the origin check refuses an untrusted page's request before any handler runs. It is the only one of the three that guards the WebSocket upgrade, which is never preflighted.

The allowlist grammar is shared with the Rust spine entry for entry: parse_allowed_origins accepts and refuses the same entries, naming each refusal with the same AllowedOriginsErrorKind string, and an accepted list matches the same origins. The shared conformance table (testing/cross_backend/origin_conformance.json) pins both.

parse_allowed_origins
#

http/origin.ts view source

(raw: string): Result<{ origins: RegExp[]; patterns: OriginPattern[]; }, { errors: AllowedOriginsError[]; }> import {parse_allowed_origins} from '@fuzdev/fuz_app/http/origin.js';

Parses an allowlist value (conventionally the FUZ_ALLOWED_ORIGINS env var) into regex matchers for request source verification. Origin allowlisting for locally-running services — not the CSRF layer (that's SameSite: strict on session cookies plus http/simple_request.ts).

Entries are comma-separated and trimmed of ASCII whitespace. Each is written the way a browser writes an Origin — scheme://host[:port] — where a whole host label or the port may be *:

  • Exact origins: https://api.fuz.dev, http://localhost:3000
  • Wildcard labels: https://*.fuz.dev (each * is exactly one label, in any position — api.fuz.dev matches, fuz.dev and a.b.fuz.dev don't)
  • Wildcard ports: http://localhost:* (any port or none)
  • IPv6 addresses: http://[::1]:3000, https://[2001:db8::1] (exact)
  • Combined: https://*.fuz.dev:*

Refused, nothing normalized: anything but printable ASCII (punycode an international hostname), a scheme other than http or https (null, file://, chrome-extension://), a path, query, fragment or trailing slash, userinfo, a character no hostname holds, a partial wildcard, an IPv4 address not written as four canonical decimal numbers (127.1), an IPv6 address not in the form a browser sends, a port outside 1..=65535 or with leading zeros, the scheme's default port, and an empty entry. Every refused entry is reported, not just the first.

verify_request_source

(allowed_patterns: readonly RegExp[], carve_outs?: readonly MiddlewareCarveOut[]): Handler import {verify_request_source} from '@fuzdev/fuz_app/http/origin.js';

Middleware that verifies the request source against an allowlist.

Origin allowlisting (not the CSRF layer — that's SameSite: strict cookies plus http/simple_request.ts):

  • Checks the one Origin line (if present) against the allowlist
  • Allows requests without an Origin header (direct access, curl, etc.)
  • Refuses a malformed Origin (read_origin of http/request_headers.ts): an empty line, a second line, a byte that isn't visible ASCII — read from the lines the client sent (get_header_lines), so a runtime's own view of a repeated or empty line (@hono/node-server rebuilds a WebSocket upgrade's from Node's deduplicated one) decides nothing

Origin-only by design — Fetch spec mandates Origin on every unsafe method (POST / PUT / DELETE / PATCH) regardless of Referrer-Policy, so every real browser request on the state-changing surface carries it. Non-browser clients (curl, server-to-server, CLI) don't ship auto- attached session cookies, so CSRF isn't the relevant threat there — auth (bearer / daemon token) is the actual control. A Referer fallback would only widen the accepted-shape envelope without closing a real CSRF hole. The Rust spine's origin_layer is the twin.

create_app_server mounts it on every path (ORIGIN_MIDDLEWARE_PATH); a request whose path a carve_outs entry matches passes unchecked — the named, explicit exception, each with its reason, as the Rust stack's origin_carve_out is.
