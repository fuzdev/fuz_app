http/route_error_check.ts

Whether an error response is one its route declares — the one rule the DEV error check (http/dev_route_error_check.ts) and the test helpers (assert_response_matches_spec) share.

A JSON body at an error status (400 and up) is declared when the route's error map (resolve_route_error_map) has that status and the body parses against it. Three exemptions: a 500 internal_error and a 503 service_unavailable (ALWAYS_ACCEPTED_ERRORS), which the catch layers answer on any route and no route declares, and, on a jsonrpc route, a JSON-RPC error envelope, which no REST error definition describes. A non-JSON response, by is_json_response, is not checked at all.

Also the hono-free route lookup the test helpers run (find_route_spec): a route's Hono path template read segment by segment (split_route_template, parse_route_param) and compiled to a RegExp (compile_route_path), and the first route in mount order matching a request, HEAD read as GET (find_mounted_route). The DEV check, on the Hono side, looks routes up with Hono's own router (create_route_lookup); the two are pinned against Hono and each other by the route-lookup tests.

Hono-free and esm-env-free.

Compile the re of a :name{re} param to the RegExp a value of the param must match, grouped and anchored at both ends, ^(?:re)$, as compile_route_path reads it inside a template. That is Hono's RegExpRouter reading; its TrieRouter, which SmartRouter falls back to for some route sets, anchors ^re$ and leaves a top-level alternation ungrouped, so ^a|b$ takes ab where the grouped form refuses it. The grouped form is the stricter of the two: a value it accepts both routers accept. Test it against the value as Hono reads it (decode_route_path).

compile_route_path
#

http/route_error_check.ts view source

(template: string): RegExp import {compile_route_path} from '@fuzdev/fuz_app/http/route_error_check.js';

Compile a Hono path template to a RegExp over request paths, reading it as Hono 4's routers do: the template is split on / with each {…} group kept whole, and each segment is a *, a param — a whole segment :name (one non-empty segment) or :name{re} (the pattern re, which may span segments) — or literal text, so a : inside a segment (files:upload, :x-:y's second) is no param of its own; a literal segment holding a * (/a*), a wildcard in Hono, throws rather than be guessed at. A template ending in ? expands its optional params as Hono's checkOptionalParameter does. A trailing /* matches the prefix with anything after it or nothing (so /api/* matches /api), a * elsewhere one non-empty segment, and * alone every path. Trailing slashes are strict, as Hono's are by default. Pinned against Hono itself by the route-lookup tests.
