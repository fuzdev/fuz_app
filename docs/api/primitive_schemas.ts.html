primitive_schemas.ts

Reusable validator-schema primitives — bounded_string, Username, UsernameProvided, Email, the branded Uuid and Datetime with their factories, and the hash schemas Blake3Hash and FactHashSchema. Lives at the top level (not inside auth/ or http/) because these shapes don't depend on or imply any domain — accounts hold a username and email, but invites, password resets, cells, and other surfaces all reach for the same primitives without going through auth.

Split out from auth/account_schema.ts so the auth module shrinks to entity types + client-safe JSON shapes (its real responsibility) and non-auth consumers can import these primitives without dragging the auth domain along. Future cross-domain primitives (phone, url, slug) land here too.

Client-safe: nothing here imports @fuzdev/blake3-wasm, so wire schemas that validate a hash don't pull the WASM binary into a bundle.

bounded_string
#

primitive_schemas.ts view source

({ min, max, max_message }: BoundedStringOptions): ZodString import {bounded_string} from '@fuzdev/fuz_app/primitive_schemas.js';

A string schema whose length is bounded in UTF-16 code units — what String.length measures, and what the Rust spine counts (encode_utf16().count()), so an astral-plane character costs two on both. Every .min() / .max() length bound on a wire string in the package is built here, bar a bare .min(1), which reads the same in either count.

Zod's .min() / .max() alone don't pin the unit: depending on the installed Zod they count code units or Unicode code points, and the peer range admits both. The schema still carries them — they are what puts minLength / maxLength in the generated JSON Schema — and a check beside them settles the verdict on String.length: it adds the over-max or under-min issue when Zod raised none, and withdraws one Zod raised for a string that is within the bound in units. The issue it adds has the fields of Zod's own and, like Zod's, lets the checks chained after it run, so a refusal reads the same whichever count Zod used.

Returns a plain ZodString, so format checks, .brand(), .nullish() and .meta() chain as usual. Don't chain a further .min() / .max() — pass the bound here.

Email
#

primitive_schemas.ts view source

value + type

string import {Email} from '@fuzdev/fuz_app/primitive_schemas.js';

Email validation. Every current consumer pairs it with Username (signup, invites, audit log), so the two live together with the other Zod primitives.

Deliberately permissive — a structural shape check (EMAIL_REGEX plus the EMAIL_LENGTH_MAX byte bound), not RFC 5322 conformance or deliverability (real delivery is proven by a confirmation email). Replaces Zod's stricter z.email() so the rule is one explicit regex the Rust spine's is_valid_email mirrors; z.email()'s internal regex (2+ char TLD, no consecutive dots) was brittle to keep in cross-impl parity and rejected addresses like a@b.c. The length bound is the UTF-8 byte count (RFC 5321 measures octets), so a multibyte address is bounded identically to the Rust spine's s.len() rather than diverging on JS's UTF-16 .length. No transform: case is preserved and surrounding whitespace is rejected (not trimmed), so storage is verbatim and the case-insensitive lookup rides the DB-side LOWER(email).

FactHashSchema
#

primitive_schemas.ts view source

ZodString & ZodType<FactHash, string, $ZodTypeInternals<FactHash, string>>

type ZodString & ZodType<FactHash, string, $ZodTypeInternals<FactHash, string>>

import {FactHashSchema} from '@fuzdev/fuz_app/primitive_schemas.js';

Wire-form schema for a blake3:-prefixed fact hash, whose output is FactHash from @fuzdev/fuz_util/hash_schemas.ts — the type fact_hash_bytes, fact_hash_stream, and FactStore use — so a parsed value passes straight to them. Client-side (cell payloads) and server-side (DB-row hashes) consumers reuse this same schema.

The output type is a cast over a plain regex check: Zod's .brand('FactHash') would output Zod's own brand, which doesn't fit fuz_util's fuz_schema-branded FactHash, and a .transform or z.custom that produced the right type makes z.toJSONSchema throw, as neither can be represented in JSON Schema. The cast costs nothing at runtime and keeps the ZodString API and the pattern in the generated JSON Schema, so .meta(), .nullable(), and z.array() compose as before.

Username

string import {Username} from '@fuzdev/fuz_app/primitive_schemas.js';

Username for account creation — starts with letter, alphanumeric/dash/underscore middle, ends with alphanumeric. No @ or . allowed.

Canonicalized to lowercase at parse time. The regex rejects whitespace outright, so .trim() is unnecessary here. Storage is canonical across every creation site (bootstrap, signup, admin-create, invite acceptance) because the schema is the single source of truth — eliminates the per-caller trim().toLowerCase() ritual and keeps the LOWER(username) = LOWER($1) lookup contract simple.

UsernameProvided
#

primitive_schemas.ts view source

value + type

string import {UsernameProvided} from '@fuzdev/fuz_app/primitive_schemas.js';

Username submitted for login or lookup — minimal validation for forward-compatibility if format rules change.

Canonicalized via .trim().toLowerCase() at parse time so login's per-account rate-limit key and DB lookup see a uniform value regardless of casing or surrounding whitespace. Mirrors the storage canonicalization on Username so submission and storage agree.

The trailing .refine rejects a whitespace-only identifier: .min(1) runs on the raw string (so " " passes it), and without the post-trim check the value would canonicalize to "" and fall through to a lookup-miss 401 instead of a 400 — an empty identifier is malformed input, not a wrong credential. Keeps the Rust spine's account_login (which rejects empty-after-trim) in parity.

Branded UUID schema. Accepts either case and outputs lowercase — the form Postgres renders a uuid in and every id the server mints — so a parsed id compares equal to the same id read back from the database. The Rust spine canonicalizes the same way.

.toLowerCase() rather than .transform(): an overwrite keeps the output type and stays invisible to z.toJSONSchema, where a transform would leave no input schema to render.
