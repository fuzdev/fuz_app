primitive_schemas.ts

Reusable validator-schema primitives, in @fuzdev/fuz_schema — bounded_string, Username with UsernameCanonical and UsernameProvided, Email, the branded Uuid with its factory, Timestamp, the hash schemas FactHashSchema and Blake3Hash, and ActingActor. Lives at the top level (not inside auth/ or http/) because these shapes don't depend on or imply any domain — accounts hold a username and email, but invites, password resets, cells, and other surfaces all reach for the same primitives without going through auth. A URL is Url from @fuzdev/fuz_util/url.ts.

Client-safe: nothing here imports @fuzdev/blake3-wasm, so wire schemas that validate a hash don't pull the WASM binary into a bundle.

acting field shared by every input that needs the caller's acting actor. Declaring acting: ActingActor on a route or action input signals to the dispatcher's authorization phase to resolve an actor against the authenticated account: it runs resolve_acting_actor, builds the actor-bound RequestContext, and loads role_grants before auth guards fire.

Resolution rules: omitted + 1 actor → use it; omitted + multiple actors → actor_required with the available list; supplied + on the account → use it; supplied + foreign actor → actor_not_on_account.

Account-grain routes — input doesn't declare acting and auth doesn't require role_grants — skip resolution entirely; their RequestContext.actor is null and the audit envelope's actor_id stays null.

Paired with RouteAuth (http/auth_shape.ts) by registry-time invariant 2: auth.actor !== 'none' ⟺ input (or query, on REST GETs) declares acting?: ActingActor. The dispatcher finds it by reference (input_schema_declares_acting), so an input declares this export, not a copy of it.

Email
#

primitive_schemas.ts view source

value + type

string import {Email} from '@fuzdev/fuz_app/primitive_schemas.js';

Email validation. Every current consumer pairs it with Username (signup, invites, audit log), so the two live together with the other primitives.

Deliberately permissive — a structural shape check (EMAIL_REGEX plus the EMAIL_LENGTH_MAX byte bound), not RFC 5322 conformance or deliverability (real delivery is proven by a confirmation email). The rule is one explicit regex the Rust spine's is_valid_email mirrors, looser than grammars requiring a 2+ char TLD and no consecutive dots, which reject addresses like a@b.c. The length bound is the UTF-8 byte count (RFC 5321 measures octets), so a multibyte address is bounded identically to the Rust spine's s.len(). No transform: case is preserved and surrounding whitespace is rejected (not trimmed), so storage is verbatim and the case-insensitive lookup rides the DB-side LOWER(email).

The max_length ahead of the grammar refuses a string past the bound in UTF-16 code units, which is past it in bytes too, before the regex reads it, and the check after it the multibyte address within the units but past the bytes, both with EMAIL_LENGTH_MESSAGE. Its JSON Schema carries the bound as maxLength.

EMAIL_REGEX
#

primitive_schemas.ts view source

RegExp import {EMAIL_REGEX} from '@fuzdev/fuz_app/primitive_schemas.js';

Loose email shape local@domain.tld: a non-empty local part, exactly one @, a domain that holds a . and neither starts nor ends with one, and no whitespace. Accepts a@b.c (single-char TLDs are fine), a@b..c and user+tag@a.co; rejects notanemail, @x.com, user@, user@host, a@.b.c, a@b.c., and any whitespace. The Rust spine's is_valid_email is the same rule.

The negated class excludes \s plus U+0085 (NEL): JS's \s omits U+0085 but Unicode White_Space (Rust's char::is_whitespace) includes it, so excluding it keeps the whitespace set identical across the twins. (The Rust side correspondingly also rejects U+FEFF, which JS \s treats as whitespace but Unicode White_Space does not — so both spines reject exactly White_Space ∪ {U+FEFF}.)

Linear in the input's length: the @ can match only the first @, and the \. only the domain's first ., since the classes before each exclude it, so the tail after the \. is scanned once. The domain spelled [^\s\u0085@.][^\s\u0085@]*\.[^\s\u0085@]*[^\s\u0085@.], the same language, is quadratic: it tries every . as the split.

Username
#

primitive_schemas.ts view source

value + type

string import {Username} from '@fuzdev/fuz_app/primitive_schemas.js';

Username for account creation — starts with letter, alphanumeric/dash/underscore middle, ends with alphanumeric. No @ or . allowed.

Canonicalized to lowercase at parse time. The regex rejects whitespace outright, so no trim is needed. Storage is canonical across every creation site (bootstrap, signup, admin-create, invite acceptance) because the schema is the single source of truth — eliminates the per-caller trim().toLowerCase() ritual and keeps the LOWER(username) = LOWER($1) lookup contract simple. A string outside the bounds and off the grammar gets the length issue alone.

UsernameProvided
#

primitive_schemas.ts view source

value + type

string import {UsernameProvided} from '@fuzdev/fuz_app/primitive_schemas.js';

Username submitted for login or lookup — minimal validation, for forward-compatibility if the creation grammar changes: at least one and at most USERNAME_PROVIDED_LENGTH_MAX UTF-16 code units, measured before trimming, holding a character that isn't whitespace.

Canonicalized to .trim().toLowerCase() at parse time, so login's per-account rate-limit key and its lookup see one value whatever the casing or surrounding whitespace, as Username canonicalizes what is stored.

A whitespace-only identifier is refused, not canonicalized to "" and left to fall through to a lookup-miss 401: an empty identifier is malformed input, not a wrong credential, and the Rust spine's account_login refuses it too. JS \s is exactly the set trim removes (ECMA-262's WhiteSpace and LineTerminator), so the regex ahead of the transform refuses what would trim to nothing.

Branded UUID schema: a UUID of RFC 9562 in either case, fuz_schema's uuid (whose grammar is UUID_REGEX), output in lowercase — the form Postgres renders a uuid in and every id the server mints — so a parsed id compares equal to the same id read back from the database. The Rust spine canonicalizes the same way. The brand goes outside the to_lower_case, which outputs a new string.

The UUID grammar of RFC 9562, in either case: five groups of hex digits, 8-4-4-4-12, with a version from 1 to 8 and the RFC's variant, or the nil or the max UUID, read case-insensitively as RFC 9562 §4 reads a UUID.
