actions/room_action_specs.ts

The room verbs' wire: the room_* request specs, the room_* notifications the registry fans out, their schemas, refusal reasons, and bounds — the TS twin of the Rust spine's fuz_actions::room specs and fuz_realtime::room_registry notification shapes.

A room is a key (RoomId) the consumer chooses and parses, holding seats (members, each with a random MemberId and a small client-encoded state) and watches (occupancy without a seat). actions/room_registry.ts holds the state and the fan-out; actions/room_actions.ts builds the handlers over it. Every verb is WebSocket-only — a room belongs to a socket — so a consumer mounts them on a WS endpoint and never on an RPC one, actor-required (acting selects the actor on a multi-actor account), and without side effects (the registry is memory, so no transaction opens).

payload and state are strings the client encodes, so both twins measure their bounds alike, in UTF-8 bytes, and charge the per-connection limiter their JSON-escaped length (json_escaped_len). Refusals carry data.reason, the ERROR_ROOM_* constants, plus rate_limited with data.retry_after. Every member event carries the room's seq (actions/room_registry.ts says what it promises).

json_escaped_len
#

actions/room_action_specs.ts view source

(text: string): number import {json_escaped_len} from '@fuzdev/fuz_app/actions/room_action_specs.js';

The bytes text takes inside a JSON string in a frame — what the room limiter charges a payload or state, and what the frame grows by. Twin of the Rust json_escaped_len, byte for byte over well-formed text.

" and \ take 2; backspace, form feed, newline, carriage return, and tab take 2 (\b \f \n \r \t); every other control character below U+0020 takes 6 (\u00XX); everything else is its UTF-8 length — U+007F and non-ASCII text are not escaped, U+2028 and U+2029 included. A surrogate pair is 4.

A lone surrogate counts 6, which is what JSON.stringify writes for one (\udXXX), so the count stays exactly the frame's growth for any string a TS handler holds. A Rust string can't hold one, and no frame delivers one to either spine: both refuse an escaped lone surrogate as a parse_error (http/json_text.ts), and a raw one is invalid UTF-8 a WebSocket refuses. So the twins never charge one differently over the wire.
