db/cell_view_sql.ts

can_view_cell in SQL — the view predicate a query applies to a cell row before LIMIT, so a page holds only rows the caller may view.

can_view_cell_sql is the one SQL form of the predicate: query_cell_list embeds it (adding the steward arm beside it), and the relation lists apply it to the cell at the other end of each edge. It binds the caller through a CellViewer (auth/cell_authorize.ts's cell_viewer_from_auth builds one from a request context), and the role-shaped grant arm reads the caller_role_grants CTE caller_role_grants_cte defines. Twin of the Rust fuz_cell::cell_view_sql.

CellViewer

CellViewer import type {CellViewer} from '@fuzdev/fuz_app/db/cell_view_sql.js';

The caller a view predicate binds — what can_view_cell reads off the request context.

role_grant_roles and role_grant_scope_ids are parallel, one entry per active role grant (null = a global grant): unnest pads the shorter with NULLs, and a NULL scope reads as a global grant, so cell_viewer_params refuses a mismatch.
