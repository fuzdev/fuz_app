primitive_schemas_fuz.ts

@fuzdev/fuz_schema twins of the Zod bounded_string, Username, Email, Uuid, UuidWithDefault, FactHashSchema (primitive_schemas.ts), and ActingActor (http/auth_shape.ts), under the same names, for schemas written in fuz_schema; UsernameCanonical, the username an output carries; UsernameProvided, the username login and lookup take; Timestamp, a timestamp on the wire; and Blake3Hash, a BLAKE3 hex hash. The last four have no Zod twin.

The output type is shared: the Zod Uuid outputs fuz_schema's Branded<string, 'Uuid'> too, and both FactHashSchemas output fuz_util's FactHash, so a value parsed by either twin goes where the other's is taken.

Both twins have one grammar, RFC 9562's read case-insensitively as its §4 says, the max UUID included, and the Rust spine's: every input gets the same verdict and output from both, and their JSON Schema is the same.

The twins are @nodocs while the Zod schemas of the same names stay, as the docs build refuses two exports of one name.

UsernameProvided
#

primitive_schemas_fuz.ts view source

value + type

string import {UsernameProvided} from '@fuzdev/fuz_app/primitive_schemas_fuz.js';

Username submitted for login or lookup — minimal validation, for forward-compatibility if the creation grammar changes: at least one and at most USERNAME_PROVIDED_LENGTH_MAX UTF-16 code units, measured before trimming, holding a character that isn't whitespace.

Canonicalized to .trim().toLowerCase() at parse time, so login's per-account rate-limit key and its lookup see one value whatever the casing or surrounding whitespace, as Username canonicalizes what is stored.

A whitespace-only identifier is refused, not canonicalized to "" and left to fall through to a lookup-miss 401: an empty identifier is malformed input, not a wrong credential, and the Rust spine's account_login refuses it too. JS \s is exactly the set trim removes (ECMA-262's WhiteSpace and LineTerminator), so the regex ahead of the transform refuses what would trim to nothing.
