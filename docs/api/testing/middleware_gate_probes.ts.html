testing/middleware_gate_probes.ts

Probes of the middleware gates a route's error map declares: a foreign Origin (403 forbidden_origin), a Host the server doesn't answer to (403 forbidden_host, the Rust spine's host gate), a declared Content-Length one byte over the route's cap (413 payload_too_large), and a Content-Length that isn't a length (400 invalid_content_length).

The map drives which probes a route gets: a gate the route's map doesn't declare — a carved-out path, a backend without the layer, a disabled limit — is not probed. Every probe is a request head with no body and no credential, so the gate answers it before auth, rate limiting or body parsing, and it leaves no state behind.

Over a socket (base_url) each probe is written raw (raw_http_send_head): fetch replaces a caller's Host and Content-Length with its own. In-process the head goes through the fixture's transport, whose Request keeps both headers as given. The unreadable-length probe runs in-process only: over a socket the runtime's HTTP parser (Node's, hyper) refuses such a length with a bodiless 400 of its own before the application sees it, and fetch can't send one. In-process the length reaches the body limit unparsed, and the 400 is the limit's own — the answer a Deno or Bun server gives when a request repeats an equal Content-Length, which those runtimes hand over joined into one value.

describe_standard_integration_tests runs one per declared gate of each route it counts and records each answer in its error coverage.
