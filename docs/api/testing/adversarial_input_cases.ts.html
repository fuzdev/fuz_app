testing/adversarial_input_cases.ts

Schema-walk generation of adversarial inputs — payloads that must fail validation.

Focused cases: one representative wrong-type value per field, one format violation per constrained field, one null and one missing case per required field, plus whole-body structural attacks (non-object body, extra unknown keys). Hono-free, so the cross-process suites reuse the generators the in-process describe_adversarial_input and describe_rpc_attack_surface_tests run.

generate_input_test_cases

(input_schema: ZodType<unknown, unknown, $ZodTypeInternals<unknown, unknown>>, options?: InputTestCaseOptions | undefined): InputTestCase[] import {generate_input_test_cases} from '@fuzdev/fuz_app/testing/adversarial_input_cases.js';

Generate adversarial test cases for a route's input schema.

Produces focused, non-redundant cases:

  • Whole-body: send array instead of object, extra unknown key
  • Missing required fields (without defaults)
  • One wrong-type value per field
  • Null for required non-nullable fields
  • One format violation per constrained field
  • String length (empty, one under minLength, one over maxLength), numeric (out of range, non-integer, off a multipleOf grid) and array-length (empty, one under minItems, one over maxItems) boundaries

Format and boundaries come from the field's input-side JSON Schema (to_field_json_schema), so a field carrying a .transform() or pipe and a .nullable() / .nullish() field get them too. A bound only a .refine() enforces generates nothing — JSON Schema can't express it.

Each per-field case is single-fault: valid except for the field it breaks. It changes one field of a valid base body — options.base when given, else one built by generate_valid_object — or, for a field that base omits, of the valid body generate_valid_object_with_field builds around it, so a case can't also break an object-level rule (adding scope_kind without its paired scope_id, or slug beside an exactly-one-of id). A field no valid body carries keeps its wrong-type and null cases on the base and gets no format or boundary cases, which would test no bound. A per-field case is emitted only when the field refuses its value, so no case is accidentally valid.

Generate adversarial test cases for a route's params schema.

Params are always strings from URL segments. Only generates cases for format-constrained fields (uuid, pattern) since unconstrained string params accept any string value, and only a violation the field refuses. Each case breaks one field of a valid params record.

Generate adversarial test cases for a route's query schema.

Query params are always strings from the URL. Generates cases for:

  • Missing required fields the field refuses to go without (a preprocessed field with a default accepts its absence)
  • Format violations on constrained fields (uuid, pattern) the field refuses

Each case breaks one field of a valid query record.
