testing/cross_backend/test_database.ts

The database a spawned test backend runs over, provisioned by the harness before the spawn and gone after its teardown.

By default it is a native pglet_server of its own (pglet speaks the Postgres wire protocol, so tokio-postgres and pg both reach it), spawned on a port the kernel picks. Under FUZ_TEST_POSTGRES_URL (FUZ_TEST_POSTGRES_URL_ENV) it is instead a PostgreSQL database of its own on that server, fuz_testing_<repo>_<name>, dropped if a killed run left it and dropped again on close() — under a session advisory lock on the name, so a second run of it fails rather than dropping the first's. Either way it starts empty, so a backend boots over nothing another run or another backend wrote.

One pglet server per database: pglet keeps one store per process and ignores the database name a client asks for, so two backends that must not share rows can't share a server. Two that must — the backend swap and both spines live — share one TestDatabase.

The pglet_server binary is built in the backend's own Cargo workspace (prepare_pglet_server_binary), whose lockfile already holds the pglet the Rust spine's fuz_testing runs, or named by PGLET_SERVER_BIN.

(bin: string): Promise<PgletServer> import {spawn_pglet_server} from '@fuzdev/fuz_app/testing/cross_backend/test_database.js';

Spawn pglet_server on a port the kernel picks (--port 0), in-memory (its default B+tree store, with real transactions), and resolve once it prints the address it listens on — it listens before printing, so it accepts connections from then on.

The server leads a process group of its own and is SIGKILLed with it by kill(), and on this process's exit, SIGINT, SIGTERM and SIGHUP, so no server outlives the run that spawned it — but a SIGKILLed vitest leaves its servers running, as it leaves its backends.
