testing/cross_backend/revocation_drivers.ts

The revocations sent on a target account's own session or by an admin that the cross-process WS and SSE round-trip suites both close a live connection on — one table, so a revocation added here is covered on both transports.

Each row drives one revocation of a target account's credentials and asserts it succeeded; the suite opens the target's connections first and asserts their close after. Each row says what it closes (AccountRevocation.closes): the whole account, or only the session the revocation was sent on (POST /logout), which leaves the account's other credentials' connections open. describe_cross_process_ws_tests and describe_cross_process_sse_tests iterate create_account_revocations. The revocations that name a credential in their input (one session, one token), a cap eviction, and those a suite drives differently (session revoke-all, account delete) stay in their suites.

The drivers are exported on their own for a consumer suite that closes a transport of its own on the same revocations.

AccountRevocationCloses

type "account" | "session"

import type {AccountRevocationCloses} from '@fuzdev/fuz_app/testing/cross_backend/revocation_drivers.js';

What a revocation row closes:

  • account — every connection of the target account, whatever credential opened it
  • session — only the connections of the session the revocation was sent on (TestAccount.create_session_headers's); the account's other sessions, its API tokens, and the daemon token stay valid, and their connections open
