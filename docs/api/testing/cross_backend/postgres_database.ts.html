testing/cross_backend/postgres_database.ts

Postgres database helpers for cross-backend global setups — creating the database a backend's URL names, and printing such a URL safely.

The harness never creates a database by itself: a setup opts in (create_cross_backend_global_setup's ensure_databases, or a call to ensure_database_for_url), so a test role without CREATEDB is never required by default.

ensure_database

(database: string, server_url?: string | undefined, deps?: EnsureDatabaseDeps): boolean import {ensure_database} from '@fuzdev/fuz_app/testing/cross_backend/postgres_database.js';

Create a Postgres database when it is missing, with createdb.

Which server it lands on depends on server_url. Given one, the database is created on the server that URL names: createdb connects through the URL with its database swapped for the postgres maintenance database, so host, port, role and query parameters all come from the URL, and a password goes to createdb in its environment, never its arguments. Without one, createdb reads the libpq environment (PGHOST / PGPORT / PGUSER).

Idempotent and never throws: a database that already exists is the quiet success case (is_createdb_already_exists). Any other failure — no createdb on PATH, no server, a role that may not create databases — is reported through deps.warn with createdb's own stderr, and whatever connects next reports a database that is really missing.
