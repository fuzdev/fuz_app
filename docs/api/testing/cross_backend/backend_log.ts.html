testing/cross_backend/backend_log.ts

A spawned backend's log, checked at teardown: spawn_backend tees the child's stdout and stderr into BackendLogConfig.path and, once the child has exited, fails the teardown on every error-level line no allowance matches. The cross-process twin of the in-process logged-error gate (testing/logged_errors.ts), at the grain of a whole run: what a backend logs isn't attributed to the test that provoked it, so an allowance names the error a suite provokes on purpose, with its reason.

An error-level line is a fuz_util Logger error (🞩error🞩, how a TS backend's errors print) or a tracing ERROR event (<timestamp> ERROR, the Rust spine's default format), or a Rust panic's first line (thread '…' panicked at), read with ANSI colors stripped. A bare console.error carries no level marker and is not seen.
