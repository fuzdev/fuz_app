testing/cross_backend/spine_suites.ts

One call that runs every shipped single-backend cross suite a backend's capabilities admit — describe_spine_cross_suites(handle, options).

A consumer's cross project otherwise wires one file per upstream suite, so a suite added here never reaches it unless someone adds the file. The one-call form runs SUITE_NAMES — the closed registry of shipped suites, each named by its module — and builds every suite's options from the handle: the paths, cookie name and capabilities from handle.config (to_cross_suite_options), the daemon token from the handle, and each suite's setup_test through default_cross_process_setup with whatever seeding that suite needs (the multi-actor keeper, the offer grantor, the cell role holder). Each suite gates its own cases on the capabilities, so a backend runs what it mounts.

Options are additive.

  • exclude names a suite with the reason it can't run on this backend; the reason is required and shows in the run as a skipped test, so a skip is stated in code and visible in the report. testing_backdoor can't be excluded, by suite or by case, nor its capabilities.testing_backdoors changed: it checks the declaration the backdoor gating reads.
  • exclude_cases names single tests of a suite that does run, each by its name path (describe titles and test name, joined with ' > ') with a required reason; one beforeEach skips them at run time, so each shows as skipped with its reason, and an entry matching no collected test of its suite fails the closing check test.
  • overrides replaces a suite's derived options, field by field (a shallow merge over what the handle gives) — a role list the backend's WS upgrade requires, an xfail for a tracked divergence, a narrower capability set. An entry can be a function of the derived options instead, for a change built on a derived value. A required option the merge leaves undefined throws at collection.
  • rpc_success_fixtures / rpc_skip_methods / rpc_input_overrides go to the standard bundle's RPC round-trip; rpc_input_overrides also seeds rpc_adversarial's params cases (each override is the valid base they break one field of). A key naming a method on neither the declared surface nor live_rpc_endpoints throws at collection.
  • ws_required_roles names the roles the backend's WS upgrade requires, so the suites that open sockets for accounts they create give them those roles.
  • suite_roles names the roles the role-shaped suites use when the backend's registry lacks the spine's own (cell_editor, participant); the call seeds the holder each needs.

Inputs the handle doesn't carry. The declared surface (surface_source, session_options, rpc_endpoints, roles) is a required option. Paths and roles that name what the reference spines mount (the role-gated WS endpoint and its roles) default to the SPINE_* constants, and a suite whose capability flag is off never reaches them. Anything else a suite needs comes from the handle when it can (session_cookie_codec's cookie_keys from the config's SECRET_FUZ_COOKIE_KEYS), else from overrides; when neither has it, the call throws naming the suite — provide it or exclude the suite.

Backdoors. The backend's capabilities.testing_backdoors must declare SPINE_SUITES_REQUIRED_BACKDOORS (the per-test reset and the audit barrier), and _testing_put_fact when it declares fact_serving; the call throws otherwise. A suite every case of which drives another backdoor (credential_deadline, origin_conformance, ws_outbound_overflow) skips itself on a backend not declaring it, shown like an exclude with a reason naming the backdoor — so an exclude, override or exclude_cases entry for it is refused as dead.

Not in the one call (STANDALONE_CROSS_SUITES, with the reasons): the suites that need two handles (the differential), a backend spawned with live limiters (login_security, ws_action_rate_limit — the standard suites would exhaust them), and the conformance runner, which runs the consumer's own cases. Each keeps its own entry point.

Suites are registered without a wrapping describe, so their test names are the same as when each is called on its own — and an exclude_cases path is the name the reporter prints after the file and any describe wrapping the call.

One beforeEach on the calling suite: it finds the test's top-level task among the ranges the suites registered, and calls ctx.skip(reason) when that suite's entries name the test's path — so the suite files stay as they are, and the test shows as skipped with its reason. A closing test holds every entry to a test its suite collected (check_spine_case_exclusions; the paths are read at collection, so a filtered run still checks them). A skipped test's own beforeEach hooks don't run, but its afterEach hooks and its suite's beforeAll still do.

(handle: Pick<ReconstructedBootstrappedBackendHandle, "config">): CrossSuiteHandleOptions import {to_cross_suite_options} from '@fuzdev/fuz_app/testing/cross_backend/spine_suites.js';

The suite options a handle's config supplies — the fields most cross suites take beside setup_test. For a suite called on its own: describe_ready_cross_tests({setup_test, ...to_cross_suite_options(handle)}) passes extra fields the suite's type doesn't list, so destructure what it takes instead when calling it with an object literal.
