testing/cross_backend/spawn_backend.ts

Spawn a test backend binary, wait for it to come up, and return a handle the test harness drives.

Lifecycle:

  1. Refuse when config.base_url's port already accepts a TCP connection — another cross run or a stale backend holds it, and the health probe would otherwise drive that process instead of the one spawned here.
  2. Write the bootstrap token (config.bootstrap.token) to config.bootstrap.token_path so the binary picks it up at startup, and delete any config.bootstrap.daemon_token_path a previous run left, so step 5 can only read the token this binary writes.
  3. child_process.spawn(...) the binary with detached: true — creates a new process group so a SIGTERM to the negative PID tears down any descendants the binary spawned (PTYs, child workers). vitest worker death + SIGINT / SIGTERM / SIGHUP handlers also fire the group teardown so ports never strand.
  4. Poll {base_url}{health_path} until it returns 2xx or startup_timeout_ms elapses — each probe bounded by its own timeout, so a listener that accepts but never answers can't outlast the deadline.
  5. Read config.bootstrap.daemon_token_path to load the binary's deterministic daemon token; thread it onto BackendHandle so _testing_reset and other keeper-credential calls can authenticate.
  6. Log one line with the time from spawn to step 5 done, so a run shows what each backend costs to bring up.

The child's stderr is kept as a bounded tail (STDERR_TAIL_MAX_BYTES): a startup failure reports it with the exit code or signal, and an exit after startup that teardown didn't cause is logged with it.

Bootstrapping (POST /api/account/bootstrap) is a separate concern — the caller composes bootstrap() from testing/transports/bootstrap.ts against a FetchTransport built around handle.config.base_url. Splitting the two keeps spawn_backend consumer-agnostic — fuz_app knows nothing about specific binary contents.

teardown

SIGTERM the child's process group — even when the child itself has exited, so no descendant outlives it — and await the group's exit, escalating to SIGKILL after a grace window. Idempotent — later calls await the same exit. A descendant that left the group — spawned detached, or one that called setsid — is out of reach and survives teardown.
