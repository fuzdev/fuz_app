testing/cross_backend/credential_wire.ts

What the raw-socket conformance suites share: the accounts that name a credential, the raw account_verify request and upgrade they send, and how they read which credential an answer is for.

Each of the three credentials belongs to a different account — the session cookie and the API token to two seeded extra_accounts, the daemon token to the keeper — so the account account_verify answers as names the credential that authenticated, and a 401 names none. credential_conformance_wire.ts and request_header_conformance_wire.ts read their rows' outcomes this way.
