testing/db.ts

Test database fixtures for parameterized testing.

Provides factory builders for creating test databases with pglet-wasm (the in-memory default), PGlite (in-memory) and pg (PostgreSQL) drivers. Consumer projects provide their own schema initialization via run_migrations and compose factories into test suites with create_describe_db (testing/describe_db.ts). Vitest-free, so the spawned spine binary's import graph (through testing/app_server.ts) can reach it.

import { create_default_db_factory, create_pg_factory, FUZ_TEST_POSTGRES_URL_ENV } from '@fuzdev/fuz_app/testing/db.ts'; import {run_migrations} from '@fuzdev/fuz_app/db/migrate.ts'; import {AUTH_MIGRATION_NS} from '@fuzdev/fuz_app/auth/migrations.ts'; const init_schema = async (db) => { await run_migrations(db, [AUTH_MIGRATION_NS]); }; const default_factory = create_default_db_factory(init_schema); const pg_factory = create_pg_factory(init_schema, process.env[FUZ_TEST_POSTGRES_URL_ENV], { suite: 'my_app' }); export const db_factories = [default_factory, pg_factory];

auth_truncate_tables
#

string[] import {auth_truncate_tables} from '@fuzdev/fuz_app/testing/db.js';

The auth namespace's row tables, in an order a DELETE per table can run in: each table before the tables it references, and role_grant_offer ahead of role_grant (the two reference each other, and the offer's side is the one that blocks). TRUNCATE … CASCADE takes them in any order.

Excludes audit_log (auth_integration_truncate_tables adds it) and the singleton rows app_settings and bootstrap_lock, which a reset restores rather than empties (reset_auth_singletons). Consumer projects spread this into their own list and add their app tables.

create_pg_factory
#

testing/db.ts view source

(init_schema: (db: Db) => Promise<void>, postgres_url: string | undefined, options: PgFactoryOptions): DbFactory import {create_pg_factory} from '@fuzdev/fuz_app/testing/db.js';

Create a pg (PostgreSQL) database factory for tests.

Skipped when postgres_url is not provided — callers pass process.env[FUZ_TEST_POSTGRES_URL_ENV]; the factory never reads the environment. postgres_url names a server and a role with CREATEDB, and is used only as the admin connection: each create() creates a database of its own there, fuz_testing_<suite>_<pid>_<thread id>_<n> from template0 (the thread id, from node:worker_threads, keeps names apart under a threads pool), opens production's pool on it and runs init_schema; close() ends the pool and drops the database WITH (FORCE). The Rust spine's fuz_testing creates and drops its databases the same way under the same prefix (its names carry no thread id), so a run of either killed before its close() leaves fuz_testing_* databases — drop them by that prefix.

create_pglet_wasm_factory
#

testing/db.ts view source

(init_schema: (db: Db) => Promise<void>): DbFactory import {create_pglet_wasm_factory} from '@fuzdev/fuz_app/testing/db.js';

Create a pglet-wasm (in-memory) database factory for tests.

Always enabled — needs the optional @fuzdev/pglet-wasm peer installed. Migrates once per init_schema: the first create() creates a pglet instance (with fuz_app's value coercion, PGLET_COERCION) and runs init_schema on it, and that migrated base is shared by every pglet-wasm factory built with the same init_schema function. Each create() returns a fork() of the base — a copy-on-write branch that shares the base's pages until written — so every database it returns is isolated from the base and from every other, and a create() never re-runs init_schema.

close(db) closes that fork; a fork is resident until then, so close every database this returns (create_describe_db does). Closing one twice is a no-op; closing a database this factory did not create throws. The base is never closed: it lives as long as init_schema is reachable.

create_pglite_factory
#

testing/db.ts view source

(init_schema: (db: Db) => Promise<void>): DbFactory import {create_pglite_factory} from '@fuzdev/fuz_app/testing/db.js';

Create a PGlite (in-memory) database factory for tests.

Always enabled — needs the optional @electric-sql/pglite peer installed. Shares one module-level PGlite WASM instance across the PGlite factories this module builds: the first create() creates it, and each create() resets its public schema (reset_public_schema) and runs init_schema, so only the first pays the WASM cold start. Every create() returns that one instance, so a create() resets the database an earlier one returned; close() is a no-op.

The instance lives as long as this module stays loaded — under the db project's isolate: false + fileParallelism: false that is the whole run; a project that isolates its files gets one per worker. A promise rather than a value, so two concurrent first create() calls build one instance, and a failed first load is the error every later create() reports.

Refuse the default database in a unit project, so a test that opens one without the .db.test.ts suffix fails naming the fix, rather than starting its own WASM instance in a parallel worker — slow, and outside whatever setup the db project gives its databases. Call it at the top of a vitest setupFiles module of the unit project, which runs ahead of every test file's imports.

It installs a builder (set_default_db_factory) whose factories refuse in create(), not when built: modules build default factories at import (testing/app_server.ts's no-db fallback), and a unit test may import them without opening a database.

reset_public_schema
#

testing/db.ts view source

(db: Db): Promise<void> import {reset_public_schema} from '@fuzdev/fuz_app/testing/db.js';

Reset a test database to a clean slate by dropping and recreating the public schema.

DROP SCHEMA public CASCADE; CREATE SCHEMA public in plain SQL, so it resets every driver: create_pglite_factory calls it on each create(), where one instance serves every suite. (create_pglet_wasm_factory and create_pg_factory need none: each create() hands out a fork or a new database.) Drift-proof — it wipes every table, type, and sequence regardless of namespace, so it needs no upkeep when the schema gains a table. The database instance remains usable after reset.

set_default_db_factory
#

testing/db.ts view source

(create_factory: DbFactoryBuilder | null): DbFactoryBuilder | null import {set_default_db_factory} from '@fuzdev/fuz_app/testing/db.js';

Install the builder create_default_db_factory uses, so suites written against the default run against another driver without being edited — create_pglite_factory to run them on PGlite. Pass null to restore pglet-wasm.

The slot is read when a factory is built, not when it creates a database, so install before the first create_default_db_factory call — a vitest setupFiles entry, which runs ahead of every test file's imports, is the shape fuz_app's own db project uses. A factory built earlier (including the module-level fallback in testing/app_server.ts) keeps the driver it was built with, and uninstalling does not revert it.
