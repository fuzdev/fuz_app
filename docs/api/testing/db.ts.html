testing/db.ts

Test database fixtures for parameterized testing.

Provides factory builders for creating test databases with pglet-wasm (the in-memory default), PGlite (in-memory) and pg (PostgreSQL) drivers. Consumer projects provide their own schema initialization via run_migrations and compose factories into test suites.

@example

import {create_default_db_factory, create_pg_factory} from '@fuzdev/fuz_app/testing/db.ts'; import {run_migrations} from '@fuzdev/fuz_app/db/migrate.ts'; import {auth_migration_ns} from '@fuzdev/fuz_app/auth/migrations.ts'; const init_schema = async (db) => { await run_migrations(db, [auth_migration_ns]); }; const default_factory = create_default_db_factory(init_schema); const pg_factory = create_pg_factory(init_schema, process.env.TEST_DATABASE_URL); export const db_factories = [default_factory, pg_factory];

assert_columns_match_live

testing/db.ts view source

(db: Db, table: string, columns: readonly string[]): Promise<void> import {assert_columns_match_live} from '@fuzdev/fuz_app/testing/db.js';

Assert a *_COLUMNS projection const names exactly the live columns of table — the drift guard for an exported const (ACCOUNT_COLUMNS, CELL_COLUMNS, a consumer's own).

This is the reverse of the fail-loud read: a named projection makes a *dropped* column fail loud at query time, but a column *added* to the table and not to the projection would silently vanish from every row read. Both directions are covered by the equality here. It guards one const; it can't see a table that has *no* const — for that, keep a table → const registry and assert its key set against query_public_columns (fuz_app's own is src/test/db/column_projections.db.test.ts).

create_pg_factory

(init_schema: (db: Db) => Promise<void>, test_url?: string | undefined): DbFactory import {create_pg_factory} from '@fuzdev/fuz_app/testing/db.js';

Create a pg (PostgreSQL) database factory for tests.

Skipped when test_url is not provided. Each create() opens a pool, resets the public schema (reset_public_schema) and runs init_schema — the lifecycle every factory here shares, so a persistent test database never carries stale DDL or tracker rows from an earlier run or another suite's schema. Point test_url at a database used only for tests.

reset_public_schema
#

testing/db.ts view source

(db: Db): Promise<void> import {reset_public_schema} from '@fuzdev/fuz_app/testing/db.js';

Reset a test database to a clean slate by dropping and recreating the public schema.

DROP SCHEMA public CASCADE; CREATE SCHEMA public in plain SQL, so it resets every driver: the in-memory factories call it on each create(), and it is recommended at the start of init_schema callbacks for create_pg_factory, whose persistent databases accumulate stale DDL across fuz_app versions. Drift-proof — it wipes every table, type, and sequence regardless of namespace, so it needs no upkeep when the schema gains a table. The database instance remains usable after reset.

db

type Db

returns

Promise<void>

mutates

  • db — drops the `public` schema and recreates it; all rows in all tables are gone after this returns.

set_default_db_factory
#

testing/db.ts view source

(create_factory: DbFactoryBuilder | null): DbFactoryBuilder | null import {set_default_db_factory} from '@fuzdev/fuz_app/testing/db.js';

Install the builder create_default_db_factory uses, so suites written against the default run against another driver without being edited — create_pglite_factory to run them on PGlite. Pass null to restore pglet-wasm.

The slot is read when a factory is built, not when it creates a database, so install before the first create_default_db_factory call — a vitest setupFiles entry, which runs ahead of every test file's imports, is the shape fuz_app's own db project uses. A factory built earlier (including the module-level fallback in testing/app_server.ts) keeps the driver it was built with, and uninstalling does not revert it.
