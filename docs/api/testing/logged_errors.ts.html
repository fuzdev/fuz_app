testing/logged_errors.ts

The per-test logged-error gate: every error a test logs — a Logger.prototype.error call or a console.error — fails the test once it ends, unless the test declared it. A test that provokes an error on purpose says so with expect_logged_error(pattern), which also asserts the error appeared, so the noise becomes coverage; an error that is a side effect of what a test or describe sets up, and not what it checks, is allow_logged_error(pattern, reason). The designed test-mode banners (LOGGED_ERROR_BANNERS) are allowed everywhere.

Wire it as a vitest setupFiles entry whose top level calls install_logged_error_gate():

// src/test/logged_error_gate.ts import { install_logged_error_gate } from '@fuzdev/fuz_app/testing/logged_errors.ts'; install_logged_error_gate();

A call counts whatever the logger's level: a Logger at 'off' prints nothing and is still a logged error, so a test's silent logger hides nothing from the gate. A test that replaces console.error with a spy has claimed the calls it swallows; a Logger call still reaches the gate first.

Errors only — warnings are not gated. An error logged outside any test (a beforeAll or afterAll, the file's top level) fails the file in its last afterAll, allowed by any allow_logged_error the file declared at collection. The check runs in the last of the test's onTestFinished hooks, after its afterEach hooks and after a create_test_app app's close, so what a shutdown logs counts. A test that already failed is left as it failed. An error a test's work logs after the test has finished — a background timer, an effect nothing awaited — lands on the next test or the file. A concurrent test runs beside its siblings, so no buffer can say whose error a log is: what it logs goes to the file's, checked in its last afterAll against the file's allowances, and both expect_logged_error and allow_logged_error throw in one — allow its errors on its describe, at collection.

(pattern: LoggedErrorPattern, reason: string): void import {allow_logged_error} from '@fuzdev/fuz_app/testing/logged_errors.js';

Allow logged errors matching pattern, with the reason they are expected: inside a test, for that test; at collection, for every test of the enclosing describe (the whole file at its top level) and for what the file logs outside its tests or in its concurrent tests. It throws in a concurrent test, whose errors share the file's bucket with its siblings', so an allowance made there would hide theirs. Unlike expect_logged_error it asserts nothing. A no-op when no setup file installed the gate.

install_logged_error_gate

testing/logged_errors.ts view source

(options?: InstallLoggedErrorGateOptions): void import {install_logged_error_gate} from '@fuzdev/fuz_app/testing/logged_errors.js';

Install the gate for the current test file — call at the top level of a vitest setupFiles module, which vitest runs ahead of each test file. Wraps Logger.prototype.error and console.error once per process (each wrapper calls the original), resets the file's state, and registers the file's hooks: a beforeEach that starts the test's buffer and checks it in an onTestFinished hook, and an afterAll that checks what was logged outside any test.
