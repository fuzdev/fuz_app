testing/transports/ws_raw_client.ts

A raw-socket WebSocket client for tests that need to misbehave, or to control exactly which bytes reach the server when.

A client library answers a close frame itself and sends nothing until its open event, so two server behaviors can't be reached through one: what the server does with a client that withholds its close frame, and what it does with frames that arrive with the handshake, before the connection can have been admitted. This speaks just enough RFC 6455 over node:net to do both — the upgrade request, masked client text frames, and unmasked server frames — and deliberately never replies to a close.

Small frames only (payloads under 64 KiB, unfragmented), which is all the JSON-RPC traffic the suites send.

type Readonly<Record<string, string>>

import {RAW_WS_UPGRADE_HEADERS} from '@fuzdev/fuz_app/testing/transports/ws_raw_client.js';

The headers that make a request a WebSocket upgrade, for a probe of what a server answers an upgrade request with — a refusal at its origin, auth or role gate — sent through any HTTP client. The key is RFC 6455's sample nonce: any 16-byte base64 value has the shape the handshake requires, and a refused upgrade never reaches the key's check.

The Host line's value, or null to write none — for an upgrade whose header_lines carry the Host lines it means to send.

type string | null

default `${hostname}:${port}`

headers?

Extra upgrade request headers — Cookie, Origin.

type Record<string, string>

header_lines?

Header lines written after headers, each Name: value, in order and as given, latin1 (one character a byte) — a name may repeat, and a byte above 0x7F goes out as itself. For an upgrade whose credential lines must reach the server exactly as a test spells them.

type readonly string[]

pipelined?

Text frames to write in the same TCP write as the upgrade request, so they are in the server's hands before the handshake is answered — and so before the connection can have been admitted.

type readonly string[]
