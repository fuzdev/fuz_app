break: the middleware-gate probes are a suite of their own, and the standard cross suite splits in two

- break: `describe_standard_integration_tests` no longer runs the middleware-gate probes; `describe_middleware_gate_tests` (`testing/middleware_gate_probes.ts`) does, over the same counted routes — an in-process caller (fuz_forge's `server.integration.db.test.ts`) adds `describe_middleware_gate_tests(default_in_process_suite_options({...}))` beside it, the same options it passes the integration suite
- break: `StandardIntegrationTestOptions` drops `base_url`, `max_body_bytes` and `rpc_max_body_bytes`, which `MiddlewareGateTestOptions` takes
- break: the integration suite's error coverage leaves out the gate refusals (`MIDDLEWARE_GATE_ERROR_CODES`: `forbidden_origin`, `forbidden_host`, `payload_too_large`, `invalid_content_length`), which the gate suite probes — a `check_uncovered_errors` list naming one of them drops it
- break: `describe_spine_cross_suites` registers the standard suites as two: `standard_auth` (new — `describe_standard_auth_cross_tests`, `cross_backend/standard_auth.ts`: integration, and admin with `roles`) and `standard` (`describe_standard_cross_tests`: the gate probes, round trip, RPC round trip, data exposure); an `overrides`, `exclude` or `exclude_cases` entry for the integration or admin suite (`check_uncovered_errors`, `error_coverage_min`, `admin_prefix`, their tests' name paths) moves from `standard` to `standard_auth`, while the round-trip, data-exposure and gate options stay on `standard`; the gate probes' tests now sit under a top-level `middleware gates` describe, not `standard_integration > middleware gates`
- break: `describe_standard_cross_process_tests` and `StandardCrossProcessTestOptions` move to `cross_backend/standard_bundle.ts` (a standalone suite), still running every standard suite, the gate probes included; `cross_backend/standard.ts` exports `describe_standard_cross_tests` and `StandardCrossTestOptions`
- feat: `is_standard_integration_route` and `MIDDLEWARE_GATE_ERROR_CODES` (`testing/integration_helpers.ts`); `CoverageFilterOptions.ignore_codes`
- feat: `create_dual_spawn_global_setup` takes `after_bootstrap(handle, side)`, run once each backend's bootstrap succeeds and before any test
- fix: `_testing_reset` stamps each seeded account's session `created_at` at the wall clock (`RESET_SESSION_CLOCK_STAMP_SQL`, byte for byte the Rust reset's), so the keeper's and the extra accounts' sessions list in seed order instead of tying on the reset transaction's `NOW()` and ordering by the random session hash
- break: `describe_standard_integration_tests`' `non-admin cannot access admin routes` and `describe_standard_admin_integration_tests`' `exercises 401/403 on admin routes for error coverage` (renamed `exercises 401 on admin routes for error coverage`) are registered only when the surface has the admin REST route they drive, rather than passing with nothing sent; on a surface without it, an `exclude_cases` entry naming one fails as naming no collected test, and a `-t` filter matches nothing. The admin test now sends without a credential (it sent through the fixture's transport, which carries the keeper's admin cookie, so the routes answered as admin and nothing was recorded) and requires a 401 from each route; it drives only the admin routes a bare request reaches the 401 on — no params, and no query field it requires — since params and query validate ahead of the 401
- feat: `describe_middleware_gate_tests` throws at collection when a gate refusal a counted route declares has no planned probe
