break: a pool checkout is bounded — `FUZ_DB_CHECKOUT_TIMEOUT_MS` (default 5000) on every request, `FUZ_DB_AUDIT_CHECKOUT_TIMEOUT_MS` (default 30000) on the audit emitter's pool writes — and a failed checkout answers 503 on every surface (`service_unavailable` -32007 `database unavailable` on JSON-RPC, flat `{"error":"service_unavailable"}` on REST, SSE, fact serving, and the credential walk) while a failed query keeps its 500, as the Rust spine answers; a throw in the RPC dispatcher's authorization phase now answers the JSON-RPC envelope rather than the REST catch's flat body; a dropped audit pool write is logged with the whole row, secret metadata masked. New: `DbCheckoutError` / `is_db_checkout_error` (`db/db_checkout_error.ts`), `create_pg_pool` and the `DEFAULT_DB_*` constants (`db/db_pg.ts`), `Db.with_checkout_timeout`, `create_db`'s `options.checkout_timeout_ms`, `create_app_backend`'s `db_checkout_timeout_ms` / `db_audit_checkout_timeout_ms`, the `BaseServerEnv` vars, `ERROR_SERVICE_UNAVAILABLE`, `DB_UNAVAILABLE_MESSAGE`, `to_dropped_audit_row`, `zod_maybe_get_field_schema`, the server's `onError` (`server/app_error_handler.ts`), `is_pg_database_url` and `CreateDbOptions` (`db/create_db.ts`), `DbCheckoutPool`, `CreatePgPoolOptions` and `DB_CHECKOUT_TIMEOUT_MAX_MS` (`db/db_pg.ts`), and the cross-backend configs' `db_checkout_timeout_ms` / `db_audit_checkout_timeout_ms` options. PGlite and pglet have no pool, so the bounds are inert there. To migrate: `create_pg_db` takes a pool from `create_pg_pool(pg, {connection_string, checkout_timeout_ms})` in place of a bare `new pg.Pool`, a server passes `env.FUZ_DB_CHECKOUT_TIMEOUT_MS` / `env.FUZ_DB_AUDIT_CHECKOUT_TIMEOUT_MS` to `create_app_backend`, and a connect error is now a `DbCheckoutError` whose `cause` is the pg error — read its SQLSTATE with `pg_error_code`
