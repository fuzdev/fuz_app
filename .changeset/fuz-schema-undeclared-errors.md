break: an error a route answers that its error map doesn't declare now fails. In DEV, `create_app_server` mounts one outer error check, outermost, so a middleware's refusal counts as much as a handler's: `create_dev_route_error_check({route_specs, route_errors, log})` (new `http/dev_route_error_check.ts`) finds the request's route with Hono's own router (`create_route_lookup`, the `SmartRouter` over a `RegExpRouter` and a `TrieRouter` that `new Hono()` builds, the route specs added in mount order, `HEAD` read as `GET`) and logs a JSON body at 400 and up whose status the route's map lacks (`Undeclared error status (418): GET /path`) or that is off the status's schema (`Error schema mismatch (409): GET /path`, as before). A 500 `internal_error` and a 503 `service_unavailable` are always accepted, a JSON-RPC error envelope on a `jsonrpc` route is skipped, as are non-JSON responses and requests no route spec matches; it logs and never changes the response, a throw inside it (its logger's included) swallowed. Outside DEV the factory returns `null` and nothing is mounted. It replaces the error half of the per-route DEV check: `apply_route_specs` drops its last `route_errors` parameter and checks only a 2xx body against `output`, so an app that mounts `apply_route_specs` itself and wants its errors checked mounts `create_dev_route_error_check` ahead of everything. The shared rule is in the new hono-free `http/route_error_check.ts`: `check_route_error`, `ALWAYS_ACCEPTED_ERRORS`, `is_error_status`, `is_json_response` (the `Content-Type` gate both checks run), `format_route_error_check`, and the test helpers' hono-free lookup, `compile_route_path` (a Hono path template read segment by segment as Hono's `getPattern` reads it), `to_mounted_routes`, `find_mounted_route`. `find_route_spec` takes the first spec in list order matching the path, as Hono dispatches, where it took an exact path first (a template passed as the path still finds its own spec), and reads `HEAD` as `GET`. The test helpers fail the same way: `assert_response_matches_spec` throws on a JSON error at a status the map lacks (`Undeclared error status (418): POST /path: {…}`), its schema mismatch now `Error schema mismatch (409): POST /path: […]`, with the same exemptions, and reads only a JSON `Content-Type` as a body to check, so the round trips and `ErrorCoverageCollector.assert_and_record` do too; `assert_error_schema_valid` also requires the body's `error` to be a code the route declares at that status; the adversarial input and 404 suites check each refusal against the route's own map rather than `InvalidInputError`, and the attack-surface suite's `correct auth passes guard` holds a JSON error a handler answers to the map through the new `assert_error_response_declared(errors, jsonrpc, response, label)`. An `error` is a code: `rest_error` throws on one off `^[a-z][a-z0-9_]*$` (`REST_ERROR_CODE_PATTERN`, `is_rest_error_code`), and a literal plainly off it — prose, uppercase, a leading digit or `_`, a space or some punctuation — is a type error, the runtime check being the authority; `fields` with an own `error` entry throws too, as it would replace the code; prose goes in `message`. New `ERROR_FORBIDDEN_HOST` / `REST_FORBIDDEN_HOST` (403 `forbidden_host`), the Rust spine's host gate, declared by `create_rust_spine_consumer_surface_spec`'s `host_validation` layer with `host_gate`, so every route of such a surface declares it. `ApiError` is deleted. `AdversarialHeaderCase.expected_error` (`testing/adversarial_headers.ts`) and `BearerAuthTestOptions.expected_error` (`testing/middleware.ts`) are `RestErrorDef`s, checked for their code, status and body, where they were a string checked against `ApiError`; the standard header cases use `REST_FORBIDDEN_ORIGIN`. The error-schema tightness checks collapse into one invariant, `assert_error_codes_specific` (every declared body's `error` is a `const` or an `enum`, routes and middleware alike), beside `assert_error_codes_well_formed` (every code matches the pattern), both in `assert_surface_invariants`; gone are `assert_error_schemas_structurally_valid`, `assert_404_schemas_use_specific_errors`, `audit_error_schema_tightness`, `assert_error_schema_tightness`, `default_error_schema_tightness`, `resolve_standard_error_schema_tightness`, `ErrorSchemaTightnessOptions`, `ErrorSchemaSpecificity`, `ErrorSchemaAuditEntry`, and `describe_standard_attack_surface_tests`' `error_schema_tightness` option and its `error schema tightness` test. In the UI, `parse_response_error` shows a body's `message` when it has one, else its `error` code, through the new `format_error_body(body, fallback)`; `TableState`'s row delete and `AuthState`'s bootstrap show refusals through it, and the delete no longer appends a `detail` field. Request verdicts and the surface are unchanged. To migrate: declare every error a route or middleware answers (`errors: [rest_error(404, 'thing_not_found')]`) — a test that drives an undeclared one now fails, and a DEV server logs it; rename any code that isn't one (`'File not found'` → `rest_error(404, 'file_not_found')`, the prose to `message`); pass `REST_*` definitions as `expected_error`; drop `error_schema_tightness` from the attack-surface options and calls to the removed tightness functions; drop `apply_route_specs`' seventh argument; read `ApiError`'s callers through the route's definitions.
