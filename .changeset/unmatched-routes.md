break: the server routes on the raw path, and a request no route answers gets one answer on both spines — 405 with `Allow`, or a 404 that is JSON under `/api/`

- break: `create_app_server` builds its app with `getPath: get_request_path` (`http/request_target.ts`): nothing is percent-decoded before the router, so `/%61pi/x` no longer reaches `/api/x`, as on the Rust spine. The auth scope, the origin carve-outs, the invalid-cookie clear and the DEV route lookup read that same raw path. `decode_route_path` is removed; `find_route_spec` and `resolve_valid_path` read the raw path
- break: a method a routed path doesn't serve answers 405 `{"error":"method_not_allowed"}` with `Allow` naming the methods the path serves (`HEAD` wherever `GET` is) — where it fell through to Hono's text 404 — on every routed path, a WebSocket endpoint's and `OPTIONS` included. A path no route serves answers 404: `{"error":"route_not_found"}` under `/api/`, the plain-text `404 Not Found` (`NOT_FOUND_TEXT`) elsewhere. Both come from `server/unmatched_route.ts`, the app's `notFound`, after the host gate and the origin check and ahead of authentication, carrying the invalid-cookie clear. New codes `ERROR_METHOD_NOT_ALLOWED` and `ERROR_ROUTE_NOT_FOUND`
- break: static serving names each file outright (`ServeStaticOptions.path`), since Hono's `serveStatic` refuses a request path holding a `%`: a path with an escape is decoded once (`to_static_file_path`), and the SPA fallback serves its file whatever the client route's spelling — so an escaped spelling the old decoded routing answered 404 (an encoded `%25` or `%2F`, a malformed escape, a doubled slash) now gets the SPA page, like any other client route outside `/api`. A custom `is_spa_route` receives the raw path
- testing: `assert_response_matches_spec` fails an answer no route gave (the 405, the JSON `route_not_found`, the plain-text 404) even where the route declares a 404, so a route on the surface that a backend doesn't mount is never a pass. `request_target_conformance.json` gains the routing rows, with `expect.allow` (a set; `[]` for absent), `text`, `media`, `clears_session`, and per-row `origin`, `host`, `headers`; a row's `requires` is a list, and the wire leg runs one test per requirement set. `BackendCapabilities` gains `runtime_resolves_dot_segments` and `spine_fallback` (both family defaults): a backend serving its own static or SPA fallback outside `/api` states `spine_fallback: false` and keeps the rest of the leg. A consumer's Rust backend needs the fuz spine of the same change, and its own fallback must hand an unmatched `/api/` path to the spine's (`route_not_found`)
