break: the REST error model and the leaf HTTP schemas are `@fuzdev/fuz_schema`, every error a route answers is one it declares, and each route's declared errors are one map of per-code error definitions, read by the surface, a DEV-only error check, and the test helpers. Request verdicts are unchanged; a committed surface snapshot changes once (below).

**What became fuz_schema.** The leaf schemas: `WireIssue` (`schema_issues.ts`), `HealthResponse` (`http/health_schema.ts`, which `ui/backend_probe.svelte.ts` reads through `loose_object(HealthResponse.def)`, so the browser probe no longer imports Zod), the bodies of `create_health_route_spec`, `create_ready_route_spec` and `create_server_status_route_spec` (`http/common_routes.ts`), `create_surface_route_spec` (`server/surface_route.ts`) and `create_audit_log_route_shape`, each `null` a `literal(null)`; `XAccelConfig` (`server/x_accel.ts`) and `FileFactUrl` (`db/file_fact_url.ts`), now fuz_schema `Branded` types; `DaemonToken`; `OriginPatternErrorKind` and `AllowedOriginsErrorKind` (`http/origin.ts`, `one_of`s: `.def` for `.options`); the cross-backend origin-conformance and action-manifest schemas (`ActionManifestEntry`, `ActionManifest`), whose `capture_*` probes take either library (new `parse_capture_answer`). The error bodies: every REST error is a definition (below). `RouteAuth` (`http/auth_shape.ts`) is an interface, the Zod schema deleted, its invariants still checked by `assert_route_auth_invariants`; `AuthAxisState` is a `one_of`; `RateLimitKey` moves to `rate_limiter.ts`, a `one_of`. Every schema of `create_db_route_specs` (`http/db_routes.ts`), and the params of `create_serve_fact_route_spec` and `create_serve_cell_fact_route_spec`, over the fuz_schema `Uuid` and a new fuz_schema `FactHashSchema` in `primitive_schemas_fuz.ts` (`brand(pipe(string, regex(FACT_HASH_EXACT)), 'FactHash')`, the same verdicts, output and `pattern` as the Zod one in `primitive_schemas.ts`, which stays). The types, read by `Infer`, keep their names and shapes but where a table below says otherwise; the role and credential-type lists are `Array<string>` where Zod typed them `ReadonlyArray<string>`.

**The error model.** `rest_error(status, code, fields?, headers?)` makes a `RestErrorDef` (its body types `RestErrorSchema`, `RestErrorBody`, `RestErrorEntries`): one code at one HTTP status, its body `loose_object({error: literal(code), ...fields})` as `.schema`, and `headers` derived from a body (`Retry-After`). Every code a route or middleware answers has one, named `REST_*` after its `ERROR_*` code (`REST_TABLE_NOT_FOUND`, `REST_RATE_LIMIT_EXCEEDED` with `retry_after`, `REST_INSUFFICIENT_PERMISSIONS` with `required_roles`, `REST_AUTHENTICATION_REQUIRED_BOOTSTRAP` for `/api/account/status`'s 401 with `bootstrap_available`, …). The `ERROR_*` strings stay and carry no status, as they double as JSON-RPC `data.reason`s; new are `ERROR_SCHEMA_DRIFT`, `ERROR_DB_UNREACHABLE`, `ERROR_INTERNAL_ERROR` and `ERROR_FORBIDDEN_HOST`. A code must match `^[a-z][a-z0-9_]*$` (`REST_ERROR_CODE_PATTERN`, `is_rest_error_code`): `rest_error` throws on one off it, or on `fields` holding an `error`, and a literal plainly off it (prose, uppercase, a leading digit) is a type error; prose goes in `message`, which the UI shows in preference to the code (new `format_error_body` in `ui/ui_fetch.ts`, read by `parse_response_error`, `TableState`'s row delete and `AuthState`'s bootstrap). `RouteSpec.errors` and `MiddlewareSpec.errors` are `ReadonlyArray<RestErrorDef>` (`errors: [REST_TABLE_NOT_FOUND, rest_error(409, 'slug_taken')]`), where they were status → schema maps; `apply_route_specs` refuses anything else at registration. A route's error map (new `http/route_errors.ts`) is the union of three layers — derived from its slots, each middleware layer that runs on it, and its own — where nothing replaces anything: a definition at a status another layer declares is one more branch there, and a repeat counts once (`same_rest_error`, `dedupe_rest_errors`). `derive_route_errors` narrows to the slots a route has: the body codes (`invalid_request_body`, `invalid_json_body`) only off `GET` and with an input, `invalid_route_params` only with `params`, `invalid_query_params` only with a `query`, the 401 `authentication_required` exactly, the 415 on every `POST`. `resolve_app_route_error_maps` builds every route's `RouteErrorMap` (`{defs, schemas}`) from a `RouteErrorMapSpec` keyed `METHOD path` by `format_route_key` (`http/surface_query.ts`, which now takes a route spec too); `create_app_surface_spec` builds them once as `AppSurfaceSpec.route_error_maps`. `create_app_server` mounts the body limit as a `*` middleware spec ahead of the others declaring 413 `payload_too_large` and 400 `invalid_content_length` (`create_body_limit_middleware_spec`, its hono-free shape `body_limit_middleware_shape` in `http/body_limit_schema.ts`; absent with `max_body_size: null`), and the origin check declares `REST_FORBIDDEN_ORIGIN`. New `RouteSpec.jsonrpc`, set by `create_rpc_endpoint`: on such a route a JSON-RPC error envelope is not a REST error body. Renamed or deleted, nothing left at the old name:

**Enforcement.** In DEV, `create_app_server` mounts one error check outermost (new `http/dev_route_error_check.ts`, `create_dev_route_error_check({route_specs, route_error_maps, log})` (`DevRouteErrorCheckOptions`, `DevRouteErrorCheckSpec`)), so a middleware's refusal counts as much as a handler's: it finds the request's route with Hono's own router, as Hono dispatches (`create_route_lookup`, `HEAD` read as `GET`), and logs a JSON body at 400 and up whose status the route's map lacks (`Undeclared error status (418): GET /path`) or that is off the status's schema (`Error schema mismatch (409): GET /path`). A 500 `internal_error` and a 503 `service_unavailable` are always accepted, an envelope on a `jsonrpc` route is skipped, as are non-JSON responses and unmatched requests; it never changes the response, and outside DEV the factory returns `null`. `apply_route_specs` checks only a 2xx body against `output` in DEV, where 0.163.0 also checked errors. The rule is shared, hono-free, in `http/route_error_check.ts` (`check_route_error` (a `RouteErrorCheck`), `ALWAYS_ACCEPTED_ERRORS`, `is_error_status`, `is_json_response`, `format_route_error_check`), with the test helpers' route lookup, which reads a template as Hono does (`split_route_template`, `parse_route_param` (a `RouteParam`), `compile_route_path`, `to_mounted_routes`, `find_mounted_route` (`MountedRoute`)). The test helpers fail the same way: `assert_response_matches_spec` throws on a JSON error at an undeclared status or off its schema, with the same exemptions, through the new `assert_error_response_declared(errors, jsonrpc, response, label)`, and reads only a JSON `Content-Type` as a body, so the round trips and `ErrorCoverageCollector.assert_and_record` do too; `find_route_spec` takes the first spec in mount order matching the path, `HEAD` as `GET`; `assert_error_schema_valid` fails a code the route doesn't declare at the status; the adversarial input and 404 suites hold each refusal to the route's own map, and the attack-surface suite's `correct auth passes guard` holds a handler's JSON error to it. `AdversarialHeaderCase.expected_error` and `BearerAuthTestOptions.expected_error` are `RestErrorDef`s, checked for status, code and body (the standard header cases use `REST_FORBIDDEN_ORIGIN`), and `expected_error_schema` is gone from both. `resolve_valid_path` fills only whole param segments, as Hono reads them, so a `:` inside a literal segment (`/v1/files:upload`) stays and a `:name{re}` is filled whole, its `test_<name>` fallback percent-encoded. The value comes from the params schema alone, never from `re`, so it can miss its own pattern (`/:slug{.+\.git}/info/refs` resolves to `/test_slug/info/refs`, which the route refuses, as it did before). A `{re}` route whose handler checks the param, which used to receive the literal `test_<name>{re}`, now gets past that check. The error-schema tightness checks collapse into `assert_error_codes_specific` (every declared body's `error` is a `const` or an `enum`) and `assert_error_codes_well_formed` (every code matches the pattern), both in `assert_surface_invariants`; gone are `assert_error_schemas_structurally_valid`, `assert_404_schemas_use_specific_errors`, `audit_error_schema_tightness`, `assert_error_schema_tightness`, `default_error_schema_tightness`, `resolve_standard_error_schema_tightness`, `fuz_app_stock_route_tightness_allowlist`, `ErrorSchemaTightnessOptions`, `ErrorSchemaSpecificity`, `ErrorSchemaAuditEntry`, and `describe_standard_attack_surface_tests`' `error_schema_tightness` option and test. `assert_input_routes_declare_400` / `assert_params_routes_declare_400` / `assert_query_routes_declare_400` require the slot's own code, the input check skipping `GET`. Error coverage reads the maps' definitions, one row per (status, code), `UncoveredEntry.code` always set, and `describe_standard_integration_tests` no longer ignores 403; its denominator now includes `forbidden_origin` and the body limit's 413 and 400 on every route.

**The surface, regenerated once.** Every route gains the body limit's 413 `payload_too_large` and 400 `invalid_content_length` and the origin check's 403 `forbidden_origin`; a status with several definitions is an `anyOf` of their bodies in order — derived, middleware, explicit. The input 400 narrows to the codes a route's slots answer, where it was one `enum` of the four. The 401 is `const: 'authentication_required'` (it was any string), each 403 names its code, and the 429's `retry_after` is `{type: 'integer', minimum: 0}`. `/ready`'s 503 is an `anyOf` of `schema_drift` and `db_unreachable` loose objects (it was a strict object over an enum). Signup, bootstrap, login and password drop their explicit body 400s and the fact routes their params 400, all now derived; `POST /api/account/password` declares the 401 `invalid_credentials` its handler answers; the db routes declare only their handlers' codes. Outputs that are counts are integers, `{type: 'integer', minimum: 0}`, on the surface and on DEV output validation: `/api/server/status`'s `uptime_ms` (`get_uptime_ms` returns whole milliseconds), `GET /tables`' `row_count`, `GET /tables/:name`'s `total`, `offset` and `limit`. That route's `offset` and `limit` query params are `{type: 'string', pattern: '^[+-]?\\d+$'}` with their bounds in the `description`, where Zod wrote integers, with one `info` diagnostic for that query; their verdicts and outputs are unchanged, a refusal's issues differ. Each `readOnly` annotation is written after its node's `type` and `items`. On a surface built by `create_rust_spine_consumer_surface_spec` with `host_gate`, every route declares 403 `forbidden_host` (new `REST_FORBIDDEN_HOST`, the Rust spine's host gate).
