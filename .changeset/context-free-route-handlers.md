break: a route handler takes the route context and never the Hono context — `(route) => result` — with the validated `input`, `params` and `query`, `auth`, and the request readers on it; `RouteSpec.response_headers` declares a route's static headers

- break: `RouteHandler` is `(route: RouteContext) => RouteResult`; a handler written `(c)` or `(c, route)` no longer typechecks. What it read from `c` is a field of `route`: `get_route_input(c)` / `get_route_params(c)` / `get_route_query(c)` (all three removed) → `route.input` / `route.params` / `route.query`, typed from the spec's schemas (`params` and `query` are `undefined` on a route that declares none; `input` is `null` on one with no body); `get_request_context(c)` / `require_request_context(c)` → `route.auth`; `get_resolved_auth(c)` → `route.credential`; `get_client_ip(c)` → `route.client_ip`; `c.req.raw.signal` → `route.signal`; `has_test_context_preset(c)` → `route.has_test_context_preset`; `c.req.query(name)` → `route.query_first(name)`; `read_json_body(c.req)` → `route.read_json_body()`; `get_header_lines(c, name)` → `route.header_lines(name)`; `c.req.raw` → `route.request`; the socket's peer address → `route.connection_ip` (recorded by the trusted-proxy middleware, not normalized, `null` without it). Middleware, the authorization phase and the WebSocket upgrade keep the Hono context and their helpers
- break: `route.auth` is typed from the spec's `auth` by `RequestContextForAuth` (`auth/request_context.ts`) — a `RequestActorContext` on an actor-required route, a `RequestContext` on an account-required one, else `RequestContext | null` — and a handler of a required tier throws (a 500) rather than run without the context its type promises, where a handler's own `?? null` fallback used to decide. A spec spread with its `auth` loosened answers 500 on every request. `HandlerForSpec` (`actions/action_types.ts`) narrows an action handler's `ctx.auth` by the same type
- break: `get_public_account_id` takes the route context (`{credential}`), not the Hono context. A `reads_credential` handler reads the account through it and never off `route.credential`, so a scope-narrowed API token stays the anonymous caller
- break: `TypedRouteHandler`, `RouteShape`, `define_route`, `define_route_shape` and `attach_route_handler` gain trailing type parameters for the input, params and query schemas; explicit type arguments to `RouteShape` need them
- feat: `RouteSpec.response_headers` — static headers every answer of the route carries from its entry on: its own validation and guard refusals, the handler's result, the error catch's 500 and 503. Checked at registration (a raw result's header rules; `Content-Type`, `Content-Length`, `Set-Cookie` and the hop-by-hop names refused), listed on `AppSurfaceRoute.response_headers`, and a result that names a declared header itself is refused. The RPC `GET` declares its `Cache-Control: no-store` there in place of a write in its handler; its answers are unchanged
- feat: `route.close_connection()` answers with `Connection: close` whatever the result, the error catch's included (a raw result may not carry the header); an SSE answer after it is refused
- fix: on `HEAD` the spine releases what a stream body holds — it cancels a raw stream body and closes an SSE stream, running its close listeners — and answers the headers with no body. A `HEAD` on an SSE route used to leave the stream admitted with nobody reading it, and on Node kept the connection open; its answer now leaves out `Connection: keep-alive`. A raw stream's `cancel` must release its source. No other `HEAD` answer changes
- break: `route_raw` refuses a `Content-Length` with a leading zero, one past the safe integer range, and one on a 204 or 205 — values Node sent as written and Bun rewrote or dropped — and a `Uint8Array` left out of bounds by a shrunk resizable buffer
- break: `PerformActionInput.auth` (a `ResolvedAuth`) is renamed `credential`
- break: `apply_route_specs` refuses at registration a `GET` spec whose `input` is not `literal(null)` (a `GET` carries no body, so nothing validated that input, and the handler's `input` and the surface's `input_schema` described a value that never arrived); declare its fields on `query`. `generate_app_surface` still describes such a spec without registering it, and `assert_mutation_routes_use_post` still flags it
- feat: in DEV, a response that should lead with a `Set-Cookie` line a middleware recorded (`EXPECTED_FIRST_SET_COOKIE_KEY` in `hono_context.ts` — the session middleware's clear of an invalid cookie) and doesn't is logged naming the method and path (`create_dev_set_cookie_check`, `http/dev_set_cookie_check.ts`, mounted by `create_app_server`): a consumer's own middleware or raw Hono route answering under `/api` with a `Response` it made. An accepted WebSocket upgrade is skipped
- testing: a hand-built `RouteContext` (a test calling a spec's `handler` itself) needs the new fields
- migrate: a handler's `c.header(name, value)` for a header every answer carries becomes the spec's `response_headers`; one a single answer carries goes on a `route_raw` result's `headers`. `c.header('Connection', 'close')` becomes `route.close_connection()`. `c.req.param(name)` becomes a `params` schema on the spec and `route.params`. A header presence check ported from `c.req.header(name) === undefined` reads `route.header_lines(name).length === 0` (`route.request.headers.get(name)` answers `null`, not `undefined`). A `HEAD` branch that released a stream by hand is deleted
