break: the test surface shares the server's assembly, test apps and `describe_db` check audit drift and database invariants by default, one auth reset, and a static daemon-token file

- fix: `create_test_app_surface_spec` assembles through `assemble_app_surface` (`server/app_surface_assembly.ts`), the function `create_app_server` builds its routes, middleware list and surface with, so the two can't drift. It had no way to list the audit event specs a server with `audit_log_sse` lists, so a committed surface snapshot built from it misses them (fuz_forge's `auth_attack_surface.json`, whose server sets `audit_log_sse: true`, lists no events). To migrate: pass `audit_log_sse` as the server does, regenerate the snapshot, and review the added events. Two errors moved with the shared assembly: when several assembly misconfigurations meet, `create_app_server` now refuses a bad `transform_middleware` after resolving the daemon-token keeper, the endpoint auth-scope checks before a missing `upgrade_websocket`, and surface generation before the WS path checks; and the stub surface's refusal of a WS endpoint with no `allowed_origins` reads `assemble_app_surface:` where it read `create_test_app_surface_spec:` — a test matching either message updates it
- feat: `create_test_app_surface_spec` takes `audit_log_sse` (a stub audit stream on the context, so `require_audit_sse` passes, and the audit event specs) and `post_route_middleware`, each its `AppServerOptions` namesake. To migrate: pass the same values both entry points get
- feat: `create_stub_app_server_context(session_cookie_name, audit_sse?)` takes the context's `audit_sse` (default `null`)
- break: `create_test_app` zero-checks the audit drift counters (`assert_no_audit_drift`) when the test that built the app finishes, resetting them at the test's first app, so every suite over apps built in its tests gets the check without `install_audit_drift_guard`. To migrate: a test that fails an audit write or writes a success row outside a transaction on purpose resets the counter once it has asserted it (`reset_audit_write_failures`, `reset_audit_success_outside_transaction` and kin); any other newly failing test has a real drift to fix
- feat: `reset_audit_drift_counters()` (`testing/audit_drift_guard.ts`) — reset every counter the drift check reads
- break: `describe_db` over a truncate list holding `account` restores the auth singleton rows between tests (`app_settings` defaults, `bootstrap_lock` unset), so a test that opens signup no longer leaks into the next, and holds each test to the database invariants (`assert_db_invariants`) when it finishes — all but `account_without_bootstrap` (`DESCRIBE_DB_DEFAULT_INVARIANT_EXCLUSIONS`: query-level suites write accounts without the spine's bootstrap; `include_db_invariants` checks it after all), and none for a test that built a `create_test_app` app on the suite's database, whose own check with the test's exclusions runs instead. To migrate: a suite whose tests write other rows the spine never would — a tombstone by query — passes `describe_db(name, fn, {exclude_db_invariants: {[invariant]: reason}})`; a test that relied on the lock or `open_signup` carrying over sets them itself
- feat: `reset_auth_singletons(db)` and `reset_auth_state(db)` (`testing/db.ts`) — the one auth reset: `describe_db`, `create_test_app_server` on a supplied `db`, and the `_testing_reset` backdoor all run it
- break: `auth_truncate_tables` lists `role_grant_offer` first, an order a `DELETE` per table runs in. To migrate: nothing, unless a consumer read the list's order
- break: `create_test_app_server` on a supplied `db` also unsets `bootstrap_lock` before the keeper bootstrap sets it again
- feat: `create_test_account_with_credentials` and `bootstrap_test_keeper` return `api_token_id` (`TestAccountCredentials`) and take `api_token_scope` (default `token_scope_full()`); `TestAppServer` carries `api_token_id`, and `TestApp.create_account` returns a `TestAppAccount` with `api_token_id` and takes `api_token_scope`. To migrate: drop a test's `SELECT … FROM api_token ORDER BY created_at DESC LIMIT 1` lookup and raw scope `UPDATE` for these (fuz_forge's `scoped_token_helpers.ts`)
- break: `testing/daemon_token_rotation.ts` is replaced by `testing/daemon_token_file.ts`: `create_daemon_token_file(runtime, deps, token_path)` writes one static token at mode `0600` and returns `{state, stop}`, its `stop` removing the file (a file already gone counts as removed; any other failure rejects) and safe to call twice. Rotation is gone (`start_daemon_token_rotation`, `DaemonTokenRotation`, `DaemonTokenRotationOptions`, `DEFAULT_ROTATION_INTERVAL_MS`): both callers pinned it never to rotate, and a rotation's write could recreate the file after `stop` removed it. To migrate: `create_daemon_token_file(runtime, {db}, token_path)` in place of `start_daemon_token_rotation(runtime, {db}, {token_path, rotation_interval_ms}, log)`, and the type `DaemonTokenFile` for `DaemonTokenRotation` (fuz_forge's `app_assembly.ts`)
