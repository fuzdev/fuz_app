break: the auth name registries and audit vocabularies are `@fuzdev/fuz_schema` schemas, not Zod, and the registry results carry only their maps. `create_role_schema`, `create_scope_kind_schema`, `create_grant_path_schema` and `create_credential_type_schema` are renamed `create_role_registry`, `create_scope_kind_registry`, `create_grant_path_registry` and `create_credential_type_registry`, and no longer return the Zod `Role`, `ScopeKind`, `GrantPath` and `CredentialType` schemas: their results `RoleSchemaResult`, `ScopeKindSchemaResult`, `GrantPathSchemaResult` and `CredentialTypeSchemaResult` are renamed `RoleRegistry` (`{role_specs}`), `ScopeKindRegistry` (`{scope_kinds}`), `GrantPathRegistry` (`{grant_paths}`) and `CredentialTypeRegistry` (`{credential_types}`); `CreateRoleSchemaOptions` is `CreateRoleRegistryOptions` and `builtin_role_specs_by_name` is `builtin_role_specs`; check membership with the map's `has`. `BuiltinRole`, `BuiltinGrantPath` and `BuiltinCredentialType` are types only, `(typeof BUILTIN_ROLES)[number]` and the like, and so is `AuditEventType` (`(typeof AUDIT_EVENT_TYPES)[number]`), which is no longer a schema value: check a string's membership with `new Set<string>(AUDIT_EVENT_TYPES).has`, as the tuple's own `includes` takes only its members. `create_name_schema` (`auth/name_schema.ts`) returns a fuz_schema `pipe` of `bounded_string` and the grammar, so `RoleName`, `ScopeKindName`, `GrantPathName` and `CredentialTypeName` are fuz_schema schemas, and so are `AuditEventTypeName` and `AuditOutcome` (`auth/audit_log_schema.ts`). `auth/role_schema_fuz.ts`, `auth/scope_kind_schema_fuz.ts` and `auth/audit_log_schema_fuz.ts` are gone: import `RoleName` from `auth/role_schema.ts`, `ScopeKindName` from `auth/scope_kind_schema.ts`, and `AuditEventTypeName`, `AuditOutcome`, `AUDIT_EVENT_TYPE_NAME_REGEX`, `AUDIT_EVENT_TYPE_NAME_LENGTH_MESSAGE` and `AUDIT_EVENT_TYPE_NAME_PATTERN_MESSAGE` from `auth/audit_log_schema.ts`. Every verdict stays, and so does every message for a string: a string both too long and off a grammar gets the one length issue where Zod added the grammar issue after it, so the startup errors of the registries, of `validate_self_service_eligible_roles` and of `create_audit_log_config` read as before for any string; a value that is no string gets fuz_schema's message (`Invalid role name "1": expected string, received number`). The wire inputs and outputs already held the fuz_schema names, so no surface or wire verdict moves. To migrate: parse these schemas with fuz_schema's `parse` / `is` or `parse_any`, and read a registry's map where its schema was read; a Zod schema can no longer hold them as a field.
