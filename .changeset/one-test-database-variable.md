break: tests opt into PostgreSQL through `FUZ_TEST_POSTGRES_URL`, and cross-backend Rust backends run on a `pglet_server` of their own

- break: `FUZ_TEST_POSTGRES_URL` (`FUZ_TEST_POSTGRES_URL_ENV`, `testing/db.ts`), the variable the Rust spine's `fuz_testing` reads, replaces `TEST_DATABASE_URL`. It names a PostgreSQL server and a role with `CREATEDB`. Anyone still setting only `TEST_DATABASE_URL` silently loses the `pg` leg, which now skips. To migrate: rename the variable in CI and scripts; an old URL that names a database still works as the admin connection
- break: `create_pg_factory(init_schema, postgres_url, {suite})` creates a database of its own per `create()` (`fuz_testing_<suite>_<pid>_<thread id>_<n>`, from `template0`; the prefix is the Rust spine's, the form differs by the thread id, which keeps names apart under a threads pool) and drops it `WITH (FORCE)` on `close()`; it no longer resets a database you name. `suite` is lowercase ASCII, digits and `_`, starting with a letter, at most `TEST_SUITE_NAME_LENGTH_MAX` (24) bytes. A role without `CREATEDB` fails saying so. A run killed before its `close()` leaves `fuz_testing_*` databases; drop them by that prefix. To migrate: `create_pg_factory(init_schema, process.env[FUZ_TEST_POSTGRES_URL_ENV], {suite: 'my_app'})`
- feat: `testing/db.ts` adds `TEST_DATABASE_PREFIX`, `TEST_SUITE_NAME_LENGTH_MAX`, `create_test_postgres_database`, `drop_test_postgres_database` and `assert_test_database_name_part`, for a test that needs a scratch database of its own
- break: a cross-backend Rust backend's database is provisioned by its global setup. `create_cross_backend_global_setup` replaces `ensure_databases` with `databases` (by backend name, the Cargo workspace and profile its `pglet_server` is built in, or `null` for PostgreSQL only), and its `configs` factories take the provisioned URL (`'memory://'` for a backend `databases` doesn't name). `create_dual_spawn_global_setup` takes `databases` per side (`DualSpawnDatabase`, `{name, pglet_server}`) and its `configs` factories take the URL the same way. `CrossBackendGlobalSetupDeps` is `{open_test_database, bootstrap_backend, postgres_url}`. To migrate: `databases: {rust: MY_CARGO_BINARY}` in place of `ensure_databases: true`, and a Rust config factory `(database_url) => …` that passes it on; delete the hardcoded test URL and any override variable
- feat: `testing/cross_backend/test_database.ts` — `open_test_database({name, postgres_url, pglet_server_bin})` → `TestDatabase` (`{url, engine, empty(), close()}`): a native `pglet_server` of its own (`spawn_pglet_server`, `--port 0`, its process group killed on `close()` and at exit), or under `FUZ_TEST_POSTGRES_URL` a PostgreSQL database `fuz_testing_<repo>_<name>` (`to_test_database_name`) dropped if a killed run left it and again on `close()`; `pglet_server_bin: null` runs it only on PostgreSQL, failing naming the variable when it is unset. Also `empty_test_database(url)`, and `prepare_pglet_server_binary({workspace_dir, profile?, bin_override?})`, which builds `cargo build -p pglet_server --bin pglet_server` in the backend's own workspace unless `PGLET_SERVER_BIN` (`PGLET_SERVER_BIN_ENV`) names a prebuilt one
- break: `make_default_rust_backend_config`'s `database_url` is the provisioned database, and `rust_spine_stub_backend_config` requires it. Removed: the `reset_db_on_startup` option on both (the builder no longer writes `FUZ_TESTING_RESET_DB_ON_STARTUP`; every database starts empty), `RUST_SPINE_STUB_DATABASE_URL_ENV` (`FUZ_TESTING_RUST_SPINE_STUB_DATABASE_URL`) and `RUST_SPINE_STUB_DEFAULT_DATABASE_URL`, and `to_shared_database_problems`' startup-reset check
- break: `testing/cross_backend/postgres_database.ts` is removed (`ensure_database`, `ensure_database_for_url`, `empty_owned_database`, `is_postgres_url`, `POSTGRES_URL_PROTOCOLS`, `EnsureDatabaseDeps`, `EmptyOwnedDatabaseOptions`). `with_database_name` and `redact_database_url` move to `db/postgres_url.ts`. To migrate: a shared-database suite's `empty_database` is the `TestDatabase`'s `empty()`, or `empty_test_database(database_url)`
- fix: `read_shared_database_snapshot` digests each table's rows client-side from every column cast to text, so the backend swap and both-live suites run on a `pglet_server`, which has no whole-row cast, `string_agg` or aggregate `ORDER BY`; the digest is now SHA-256 over the sorted rows
