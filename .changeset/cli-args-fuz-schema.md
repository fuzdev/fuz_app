**breaking** feat: the CLI arg surface takes `@fuzdev/fuz_schema` object schemas instead of Zod's — `parse_command_args` and `create_extract_global_flags` in `cli/args.ts`, which parse with `args_parse` from `@fuzdev/fuz_util` `0.73.0`, and `CommandMeta.schema` and `HelpOptions.global_args_schema` in `cli/help.ts`. `parse_command_args` returns `{ok: true, value}` or `{ok: false, error}` in place of `{success: true, data}` or `{success: false, error}`, typed by `ParseCommandArgsResult<T>`, which replaces `ParseResult<T>`; `error` lists each issue as fuz_schema's `format_issue` text on a line of its own, like `verbose: expected boolean, received string`, instead of Zod's `prettifyError` text. Aliases are read with `meta(entry, {aliases})` on any wrapper layer of an entry. The peer floor of `@fuzdev/fuz_util` is `>=0.73.0`, and `@fuzdev/fuz_schema` `^0.2.0` is a new required peer. Zod stays the schema library everywhere else in the package

- to upgrade: write each command's and the globals' schema with fuz_schema, importing `* as s` from `@fuzdev/fuz_schema/schema.ts` and `meta` from `@fuzdev/fuz_schema/meta.ts` — `z.strictObject({...})` becomes `s.object({...})`, `z.boolean().meta({description, aliases: ['v']}).default(false)` becomes `s.with_default(meta(s.boolean, {description, aliases: ['v']}), false)`, and `_: z.array(z.string()).default([])` becomes `_: s.with_default_fn(s.array(s.string), () => [])`, because a `with_default` value is the same object on every parse; read `result.ok` and `result.value` where you read `result.success` and `result.data`
- help: each arg's type is `format_schema_type`'s, so a string literal shows as `"dev"` where it showed `'dev'`, a union as its options (`string | number | undefined` where it showed `union | undefined`), and an object as its entries (`{a: number}` where it showed `object`). A string default shows as JSON, `(default: "dev")` where it showed `(default: 'dev')`, and an array default as its items, `(default: ["a","b"])` where every array showed `[]`. A `with_default_fn`'s default is made by calling its function. `format_arg_name` takes the new `HelpArgProperty`, read from a schema by the new `to_help_arg_properties`, in place of fuz_util's `ZodSchemaProperty`, and the new `format_arg_default` formats a default
- an alias declared under a wrapper, like `.meta({aliases}).default(x)` in Zod, now expands in `parse_command_args` too, where `args_parse` from `@fuzdev/fuz_util` `0.72` read it only on the outermost layer and refused the alias as an unknown key
- fix: `create_extract_global_flags` treats both entries of a `no-` pair like `color` and `no-color` as global flags. It used to skip `color`, as help output does, so `--no-color` (which `argv_parse` reads as `color: false`) and `--color` and `color`'s aliases landed in `remaining` while the extracted flags kept their defaults. Help still shows such a pair once, as `--no-color`. An invalid value for either entry now gives the fallback flags, as an invalid value for any global flag does, where `color`'s used to fail the command's parse as an unknown key
