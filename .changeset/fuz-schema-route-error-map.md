break: a route's declared errors are one map of error definitions, the union of what its slots derive, what each middleware layer that runs on it declares, and its own. `RouteSpec.errors` and `MiddlewareSpec.errors` are `ReadonlyArray<RestErrorDef>` (`[REST_TABLE_NOT_FOUND, REST_ROW_NOT_FOUND]`), where they were a status → schema map, so a Zod error entry is impossible by type and `apply_route_specs` refuses anything but a list of definitions at registration (`errors[1] is not an error definition`, naming the route); an entry left `undefined` no longer exists. `derive_error_schemas` is renamed `derive_route_errors({method, auth, has_input?, has_params?, has_query?, rate_limit?})`, its options `DeriveErrorSchemasOptions` → `DeriveRouteErrorsOptions`, and returns definitions narrowed to the slots a route has: the body codes (`invalid_request_body`, `invalid_json_body`) only off `GET` and with an input, `invalid_route_params` only with `params`, `invalid_query_params` only with a `query`, the 401 as `REST_AUTHENTICATION_REQUIRED` (it was `ApiError`, any string), the 415 by `method === 'POST'` (`checks_content_type` is gone). `merge_error_schemas`, `strip_undefined_error_schemas` (`http/schema_helpers.ts`) and `collect_middleware_errors` (`http/surface.ts`) are replaced by `resolve_route_errors(spec, middleware_specs?)`, which unions where they replaced — a middleware or explicit definition at a derived status is one more branch, and one middleware layer no longer replaces another's — dedupes identical definitions (`same_rest_error`, `dedupe_rest_errors`), and keeps two shapes of one code (`RouteErrors`: `{defs, schemas}`); `resolve_app_route_errors`, `get_route_errors` and `route_errors_key` key the maps `METHOD path`. `create_app_surface_spec` builds them once as the new `AppSurfaceSpec.route_errors` (`GenerateAppSurfaceOptions.route_errors` takes a prebuilt one), and `create_app_server` passes the same map to `apply_route_specs`'s new last parameter, so the DEV output check now sees middleware definitions, as the surface did. `get_route_errors(route_errors, spec)` resolves a route alone only when given no map, and throws naming the route's key when a given map lacks it. New `RouteSpec.jsonrpc`, set by `create_rpc_endpoint` on its pair: on such a route the DEV output check and `assert_response_matches_spec` leave a JSON-RPC error envelope (the endpoint's refusals, now at statuses the middleware declare) unchecked; on any other route an envelope-shaped body is checked like any error body. `ErrorSchemas` is `Record<number, AnySchema>`, a status map of fuz_schema schemas; `ErrorSchemaEntry` and `DerivedErrorSchemas` are gone, and `to_error_schemas` takes definitions. The origin check declares `[REST_FORBIDDEN_ORIGIN]` where it declared `{403: ApiError}` (the stub in `testing/stubs.ts` too), and `create_app_server` mounts the body limit as a `*` middleware spec ahead of the others (`create_body_limit_middleware_spec`, its hono-free shape `body_limit_middleware_shape` in `http/body_limit_schema.ts`) declaring 413 `payload_too_large` and 400 `invalid_content_length`, absent with `max_body_size: null`; `create_test_app_surface_spec` lists the same (new option `max_body_size`). Route declarations: signup, bootstrap, login and password drop their explicit body 400s and the fact routes their params 400, all now derived; `POST /api/account/password` declares the 401 `invalid_credentials` its handler answers; db_routes' `GET /tables/:name` and `DELETE /tables/:name/rows/:id` declare only their handlers' codes; `/ready`'s 503 is `[REST_SCHEMA_DRIFT, REST_DB_UNREACHABLE]`, loose objects (it was a strict object over an enum); `REST_RATE_LIMIT_EXCEEDED`'s `retry_after` is a non-negative integer, as both spines send. The surface stays status-keyed: a status with several definitions is an `anyOf` of their bodies in order — derived, middleware, explicit — where the input 400 was one enum of the four codes. In the testing helpers, `assert_response_matches_spec` takes an optional `route_errors` last, `new ErrorCoverageCollector(route_errors?)` reads coverage from the maps' definitions, one row per (status, code), `UncoveredEntry.code` always set, and `get_route_error_schema` / `assert_error_schema_valid` take the `route_errors` map; the standard integration, admin, round-trip and attack-surface suites pass `surface_source.route_errors`, so their declared paths include the middleware's. `extract_declared_error_codes` and `extract_404_error_code` are gone (`describe_adversarial_404` uses a route's first 404 definition), as is `fuz_app_stock_route_tightness_allowlist`; `default_error_schema_tightness` is `{}`, exempting no status. `assert_input_routes_declare_400` / `assert_params_routes_declare_400` / `assert_query_routes_declare_400` (`testing/surface_invariants.ts`) now require the 400 to name the slot's own code (`invalid_request_body`, `invalid_route_params`, `invalid_query_params`), and the input check skips `GET` routes. `describe_standard_integration_tests`' error coverage drops its `ignore_statuses: [403]`, and its denominator, the route error maps, now includes `forbidden_origin` and the body limit's 413 and 400 on every route, so a consumer with a tight `error_coverage_min` may need to lower it or cover those. To migrate: write each `errors` as a list of `rest_error` definitions (`errors: [REST_TABLE_NOT_FOUND, rest_error(403, 'forbidden', {required: string})]`), dropping entries the derivation now covers; read a route's declared errors through `surface_spec.route_errors` or `resolve_route_errors`; add `'body_limit'` first to an `expected_api_middleware` list; and regenerate committed surface snapshots — every route gains the body limit's 413 and 400 and the origin's `forbidden_origin` 403, input 400s narrow, and 401s, 403s and 429s tighten.
