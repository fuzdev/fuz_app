break: route results are data and the spine builds the response after the commit — `route_raw` takes `{status, headers, body}`, a session cookie rides on `route_ok`, and an SSE route answers with `route_sse`

- break: `route_raw({status, headers?, body?})` replaces `route_raw(response)`; a handler can no longer return a `Response` (`RouteRaw.response` is gone). The result is checked inside the route's transaction (a refusal is a 500 and a rollback): the status is an integer 200–599; no header in `ROUTE_RAW_REFUSED_HEADERS` (`set-cookie`, `connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, `te`, `trailer`, `upgrade`), no name twice in any case, no empty value; a body needs a `Content-Type` and can't ride a 204, 205 or 304; `Content-Length` is one run of digits and, with a text or bytes body, equals its byte length (free with no body or a stream); the body is `null`, a string, a `Uint8Array` an unlocked `ReadableStream`; bytes over a detached buffer are refused. A stream body the route ends up not answering with is cancelled
- break: the response is built after the commit, by `emit_route_response`, from what `prepare_route_response` checked inside the transaction (`PreparedRouteResponse`); `to_route_response` is removed. A response that can't be built after the commit is logged naming the route and answered 500
- break: `route_ok(value, {set_cookie?})` carries the success's own `Set-Cookie` lines (`RouteOk.set_cookie`, `[]` when none — a deep-equal against `{ok, value}` now fails), written after the context's. `set_session_cookie`, `clear_session_cookie`, `create_session_and_set_cookie` and `CreateSessionAndSetCookieOptions` are removed: build the line with the new `session_cookie_header(signed_value, options)` or `clear_session_cookie_header(options)` (`auth/session_cookie.ts`) and return it on the result; mint with `create_capped_session`. A failure can't carry a cookie
- fix: a cookie is sent only for work that committed. A login or signup whose commit failed answered its 500 carrying the new session's cookie, and a logout whose commit or audit write failed answered with the clear while the session stayed live
- fix: every route result carries the clearing `Set-Cookie` for an invalid session cookie, a raw answer of any body kind and an event stream included, since the spine builds them all through the context
- break: an SSE route opens its stream with `route.open_sse(options)` (`RouteContext.open_sse`, required; `RouteOpenSseOptions`, `RouteSseOpener`) and returns `route_sse(stream)` (`RouteSse`). Opening writes nothing on the context: the response is built when the route answers, with `SSE_RESPONSE_HEADERS` (`realtime/sse_constants.ts`), so a route that opens a stream and then refuses no longer answers with the stream's framing headers; a stream it opened and didn't answer with is closed. `create_sse_stream` (`realtime/sse.ts`, returning `OpenedSseStream`) is the opener `create_app_server` wires; `create_sse_response` keeps its signature for a handler outside the route system; a hand-built `RouteContext` (a test calling a spec's `handler` itself) must supply `open_sse`
- break: `apply_route_specs(app, specs, resolver, log, db, {authorize?, open_sse?})` takes its sixth parameter as an options object (`ApplyRouteSpecsOptions`); a hand-assembled app passes `open_sse: create_sse_stream`, or a route that opens a stream answers 500
- testing: `stub_handler` answers a `route_raw` text result
- migrate: a `c.text(body, status, headers)` or `new Response(body, {status, headers})` passed to `route_raw` becomes `route_raw({status, headers: {'Content-Type': …, ...headers}, body})` — a body needs its `Content-Type` spelled out. A pass-through of foreign headers (a CGI head) must drop `ROUTE_RAW_REFUSED_HEADERS` names itself, since the prepare refuses them rather than dropping them, and must give a `Content-Type` when the source omits one. A file download needs no `Content-Length`; a stated one must equal the byte length. A test that read a handler's `Response` through `to_route_response(c, result)` reads `emit_route_response(c, prepare_route_response(result, {label, opened_sse: new Map()}))`
