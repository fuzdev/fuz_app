break: the cross-backend setups check the auth schema's database invariants after every test, through a new `_testing_db_invariants` backdoor cross-process, and the in-process keeper is an admin by default

- feat: `testing/db_invariant_queries.ts` — `DB_INVARIANTS`, named SQL checks one set of which serves both spines, run as one statement (`DB_INVARIANTS_SQL`): no session or API token of a tombstoned account; no pending role-grant offer with a dead party; no unclaimed invite from a dead or purged issuer (resolved through its `invite_create` audit row once a purge has nulled `created_by`); a bootstrapped database keeps a live keeper and a live admin, and an unbootstrapped one has no account; an actor's tombstone agrees with its account's; an offer's recipient actor belongs to its recipient account; a claimed-by invite records its claim time; and, over `audit_log` so an undelete hides nothing, no pending offer, unclaimed invite, or credential older than a successful removal of its account (ordered by the audit `seq` of the row's create event where both spines write one). `query_db_invariant_rows` and `query_db_invariant_violations(deps, exclude?)` read them, `to_db_invariant_violations` groups rows a backend answered. Vitest-free, so a test binary mounts it. `db_invariants.gen.sql.ts` writes the statement to `testing/db_invariants.sql`, which the Rust spine's `fuz_testing` embeds byte for byte
- feat: `testing/db_invariants.ts` — the hooks: `assert_db_invariants(deps, label, exclude?)` over a database, `assert_db_invariant_rows` over rows a backend answered, `register_db_invariants_check` and `check_db_invariants_after_all`, the per-test and per-describe checks
