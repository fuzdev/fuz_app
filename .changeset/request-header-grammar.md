break: one strict reader per gate header, over the lines the client sent

- break: `Origin`, `Referer`, `Host` and `Content-Type` are read from the request's header lines (`get_header_lines`) by the pure readers of the new `http/request_headers.ts` — `read_origin`, `read_host`, `read_content_type`, each a `HeaderRead` (`absent`, `one`, `refused`). An empty line, a second line, a byte off the grammar, or a comma anywhere in the value reads `refused`, so a repeat is refused the same on a runtime that shows each line and on one that joins them. The Rust spine's `fuz_http::request_headers` reads the same rule; `testing/cross_backend/request_header_conformance.json` holds both to it
- fix: on `@hono/node-server` a WebSocket upgrade's own `Headers` drop empty values and keep the first `Host` and `Referer` line, so an upgrade with an empty `Origin` passed the origin check, a bearer or daemon token beside an empty `Referer` authenticated, and a loopback `Host` ahead of a second one passed the host gate. The upgrade is now read line by line like every request: 403 `forbidden_origin`, the credential discarded, 403 `forbidden_host`
- break: a `Content-Type` sent twice, empty, off the `type/subtype` grammar, or holding a comma is 415 `unsupported_content_type` on every `POST` route, `raw_body` routes included (two lines whose first carried a parameter read as JSON once joined; a `raw_body` route took two lines, or an empty one)
- break: `is_browser_context` moves from `http/origin.ts` to `http/request_headers.ts` and takes `(origin_lines, referer_lines)`; `is_cors_simple_content_type`, `is_json_content_type` and `is_post_content_type_refused` take the `HeaderRead` of `read_content_type` in place of the header string; `allows_request_hosts` refuses a `Host` holding a comma
- testing: the `request_header_conformance_wire` suite joins `describe_spine_cross_suites` (each table row as an RPC `POST` and as a WebSocket upgrade over a raw socket; it assumes the backend's own origin allowed, and `overrides` names another). `BackendCapabilities` gains the required `ws_upgrade_runtime_refusals` and `host_gate` — the family defaults carry both (`host_gate: true`), a hand-written capabilities literal adds them; a backend running with `host_gate: false` declares it and skips only the rows the host gate refuses. `RawHttpRequest.host` takes `null` and `connect_raw_ws` a `host` option, to send a request's own `Host` lines; the `CREDENTIAL_*_ACCOUNT_*` constants move to `testing/cross_backend/credential_wire.ts`. A consumer's Rust backend needs the fuz spine that refuses a repeated `Content-Type`
