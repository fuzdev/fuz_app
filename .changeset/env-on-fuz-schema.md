break: the env API moves from Zod to `@fuzdev/fuz_schema`, whose peer range is now `^0.5.1`. `BaseServerEnv` is a fuz_schema strict `object` (type `Infer<typeof BaseServerEnv>`), and `load_env`, `env_schema_to_surface` and the `env_schema` option of `create_app_server`, `generate_app_surface` and `create_test_app_surface_spec` take a fuz_schema object schema, throwing a `TypeError` for one that isn't. `load_env` leaves an unset var out of the object it parses: the returned env has no key for an unset var without a default (`'X' in env` is false, `Object.keys` skips it), and a field that takes `undefined` only as a value (`unknown`, `literal(undefined)`, a union with `undefined`) now fails when its var is unset. `EnvValidationError` is constructed as `(raw, issues)`, its `zod_error` replaced by `issues` (fuz_schema `SchemaIssue`s), and `format_issues()` writes fuz_schema's `format_issue` text. The numeric vars (`PORT`, `FUZ_DB_CHECKOUT_TIMEOUT_MS`, `FUZ_DB_AUDIT_CHECKOUT_TIMEOUT_MS`) now read as the Rust spine reads them: trimmed of Unicode `White_Space`, then decimal digits after at most one `+`, so `5e3`, `0x1F90`, `1.5` and a blank value are refused. New: `env_integer({min?, max?})` and `EnvStringbool` (`env/env_schemas.ts`), the twins of the Rust spine's integer and `parse_stringbool` readers, and `find_schema_sensitivity` (`sensitivity.ts`), the strongest `sensitivity` on any schema a field reaches, a key `sensitivity.ts` declares on fuz_schema's `SchemaMeta`. To migrate: replace `BaseServerEnv.extend({...})` with `object({...BaseServerEnv.def, ...})`; write app env fields in fuz_schema with `meta(schema, {description, sensitivity})`, `env_integer` for `z.coerce.number().int()`, `EnvStringbool` for `z.stringbool()`, and `optional(...)` for a var that may be unset; test an unset var with `env.X === undefined`; read `error.issues` for `error.zod_error.issues`; and spell numeric env vars in decimal digits.
