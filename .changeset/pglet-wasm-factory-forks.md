break: `create_pglet_wasm_factory` migrates once per `init_schema` and forks that base per `create()`, and the test apps and fixtures close the databases they create

- break: `create_pglet_wasm_factory` (the default `create_default_db_factory` driver) runs `init_schema` once per function, on a base shared by every pglet-wasm factory built with that function, and each `create()` returns a copy-on-write `fork()` of it, isolated from the base and every other fork. A `create()` no longer resets a shared instance, so two databases from it are independent. A fork stays in memory until `close(db)`, which closes it; a second close is a no-op, and closing a database the factory did not create throws. An `init_schema` that leaves a `BEGIN` open makes `create()` reject `25001`. `reset_public_schema` stays exported, but only `create_pglite_factory` calls it per `create()` now. To migrate: pair every `factory.create()` with `factory.close(db)` (`create_describe_db` already does), and hoist `init_schema` to module scope so factories share a base rather than each migrating its own
- break: `TestAppServer.cleanup()` and the backend `create_test_app_server` builds without a `db` now close that database, so reading it after `cleanup` rejects. `create_test_app` closes it with the app, or, for an app built in a test, after the invariant check when the test finishes; a failed keeper bootstrap or `create_app_server` closes it before rethrowing. To migrate: read the database before `cleanup`, and for an app built in `beforeAll` run the check ahead of the close — `check_db_invariants_after_suite` inside the `afterAll` that calls `cleanup`; an `afterAll(cleanup)` that runs before `check_db_invariants_after_all`'s hook (vitest runs `afterAll` hooks in reverse registration order) now fails the check on a closed database
- break: `TestFixture` gains `close()`: in-process it closes the test app and its database, cross-process it is a no-op. The shipped round-trip, RPC round-trip, data-exposure, middleware-gate and credential-deadline suites close their `beforeAll` fixture after its check. To migrate: a hand-built `TestFixture` adds `close`
- feat: `check_db_invariants_and_close_after_all(get_fixture)` in `testing/db_invariants.ts` — one `afterAll` that checks a fixture, then closes it whatever the check found, a violation thrown ahead of a failing close; its body is `check_db_invariants_and_close(suite, fixture)`
- feat: `testing/app_server.ts` exports `init_test_auth_schema`, the auth-only `init_schema` the shipped suites share, and `testing/close_after_error.ts` `close_after_error(close, error)`, which runs a close after a failure and rethrows it, aggregating a failing close after it
