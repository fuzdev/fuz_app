break: error coverage counts each declared code at a status apart, and `describe_standard_integration_tests` takes a required `base_url`.

**Counting.** `ErrorCoverageCollector.record` with a `code` (and `assert_and_record`, which reads it from the body) covers that (route, status, code) alone; it used to also mark the status covered, so any recorded code covered every code declared there. `record`'s `code` is required, `string | null`: `null`, for a response that carries none, is the one way to cover every code at a status, so any-code coverage is asked for and never had by leaving the code out. `assert_and_record` records `null` for a body with no `error`, and throws when the body was consumed and no `code` was given. Coverage figures go down wherever responses shared a status across codes — a `forbidden_origin` 403 no longer covers `credential_type_required` — so a tight `error_coverage_min` may need the missing codes driven.

**Middleware gates.** `describe_standard_integration_tests` counts the middleware errors it declares on each route by probing them: a new middleware-gates group sends each counted route (login, logout, password, signup, the RPC pair) one bodiless, credential-free request head per gate the route's error map declares — a foreign `Origin` → 403 `forbidden_origin`, a foreign `Host` → 403 `forbidden_host` where the surface declares the Rust spine's host gate, a declared `Content-Length` one byte over the route's cap → 413 `payload_too_large`, and, in-process only, an unreadable `Content-Length` → 400 `invalid_content_length` — and records each refusal in its error coverage. A gate the map doesn't declare on a route (a carve-out, a backend without the layer, `max_body_size: null`) gets no probe. The suite also records the error responses it already asserted, each with its code: signup's 403 `no_matching_invite` and 409 `signup_conflict`, the `/login`, `/logout` and `/password` 401s, and the admin route's 403; the admin suite's 401/403 probes record their codes too. The code-less records of the RPC endpoint's 401s are gone, as its refusals are JSON-RPC envelopes and no surface declares a REST 401 there. A counted route whose path has a param or wildcard is refused (`plan_middleware_gate_probes` throws) rather than probed at its literal template. The probes live in the new `testing/middleware_gate_probes.ts` (`plan_middleware_gate_probes`, `send_middleware_gate_probe`, `assert_middleware_gate_refusal`, `format_middleware_gate_probe`, `MiddlewareGateProbe`).

**Options.** `StandardIntegrationTestOptions` takes `base_url` (required: the backend's socket, which the probes write to with `raw_http_send_head`, since `fetch` replaces a caller's `Host` and `Content-Length`; `null` in-process), `max_body_bytes` and `rpc_max_body_bytes`, the backend's caps when they aren't the spine default, and `check_uncovered_errors`, called with the declared paths the suite left uncovered before the floor is asserted, for a wiring that holds its coverage to an exact set. `StandardCrossProcessTestOptions` takes the same, `base_url` required, and `describe_spine_cross_suites` forwards the handle's `base_url` and its `rpc_max_body_bytes`. `default_in_process_suite_options` gives `base_url: null` and `max_body_bytes` from `app_options.max_body_size`, and passes `max_body_size` and `origin_carve_outs` to the surface it builds, so a disabled limit or a carved-out route is no longer declared, nor probed. `raw_http_send_head` takes `host`, the `Host` to send in place of the base URL's, and throws on a CR or LF in the host or a header name or value.

It stays required rather than defaulting to in-process: a suite can't tell a socket transport from an in-process one, and a cross-process run left without it would send the probes through `fetch`, which drops their `Host` and `Content-Length`, and fail on answers the gates never gave.

**To migrate:** a caller of `record` passes the body's code, or `null` for a response without one; a direct caller of `describe_standard_integration_tests` or `describe_standard_cross_process_tests` passes `base_url`, and the backend's caps where they differ from the default; callers through `default_in_process_suite_options` or `describe_spine_cross_suites` need nothing, beyond the `rpc_max_body_bytes` a backend with its own RPC cap already passes.
