break: the name grammars beside `RoleName` no longer admit a run of underscores, so every name is one grammar: `GRANT_PATH_NAME_REGEX` (`auth/grant_path_schema.ts`), `CREDENTIAL_TYPE_NAME_REGEX` (`auth/credential_type_schema.ts`), `SCOPE_KIND_NAME_REGEX` (`auth/scope_kind_schema.ts`) and `TOKEN_SURFACE_NAME_REGEX` (`auth/token_scope.ts`) are `/^[a-z]+(?:_[a-z]+)*$/`, `ROLE_NAME_PATTERN`'s grammar, runs of lowercase letters joined by single underscores, where `/^[a-z][a-z_]*[a-z]$|^[a-z]$/` refused only a leading or trailing underscore, so `a__b` passed; `ScopeKindName`'s length cap is unchanged, and `a_b_c` still passes. `GrantPathName`, `CredentialTypeName` and `ScopeKindName` say so in their message: `Grant-path names must be lowercase letters and underscores (a-z_), no leading, trailing or consecutive underscores`, and the same for credential-type and scope-kind names. A registered name with a run now throws at construction (`create_grant_path_schema({a__b: {}})` throws `Invalid grant-path name "a__b": Grant-path names must …`, as do `create_credential_type_schema` and `create_scope_kind_schema`), and a route spec declaring `auth.required_scope: 'surface:a__b'` throws at registration (as does a direct `require_token_scope('surface:a__b')` call), `is_route_scope_capability` refusing it, with the error's text naming the grammar: `where a surface name is runs of lowercase letters joined by single underscores`. These grammars are checked here only where a name is declared, never on a request, so no surface node, action input or stored row moves, and a committed surface snapshot needs no regenerating for this; the `scope_kind` the grant inputs take is now a `ScopeKindName`, see `scope-kind-input-grammar`. The Rust spine's `SurfaceCapability` holds the same grammar for a `surface:` name. To migrate: rename a grant path, credential type, scope kind or route surface whose name has a run of underscores; a `scope_kind` already stored on a grant or an offer is read as before.
