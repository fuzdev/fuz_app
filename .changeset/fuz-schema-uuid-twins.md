break: the `Uuid` type (`primitive_schemas.ts`) is now `@fuzdev/fuz_schema`'s `Branded<string, 'Uuid'>`, the output of new fuz_schema twins of `Uuid`, `UuidWithDefault` and `ActingActor` in `primitive_schemas_fuz.ts` (same names, for inputs written in fuz_schema), so a value parsed by either library goes where the other's is taken; the Zod `Uuid` keeps its runtime behavior and JSON Schema, and its output was Zod's `z.$brand<'Uuid'>`. The twin `Uuid` is `brand(pipe(string, uuid, to_lower_case), 'Uuid')` and differs from the Zod one on the max UUID alone, which it takes in any case and lowercases, where `z.uuid()` takes it in lowercase only. `input_schema_declares_acting` and the `actor !== 'none'` registration check accept a fuz_schema input declaring the twin `ActingActor`, found by reference as the Zod one is, so an actor-axis action can take a fuz_schema input. `parse_acting`, the `acting` selector read of both dispatchers, the status route and the WS upgrade, reads by the twin's grammar: an uppercase max UUID is now a selector, naming no actor, where it read as malformed (as omitted, for an action and the WS upgrade). An actor-axis action and the WS upgrade answer `actor_not_on_account` (on a single-actor account they resolved the sole actor before: the action then refused the input, the upgrade succeeded); the status route still answers account-only. A declared gap remains: a Zod `Uuid` input field and a route's `?acting=` query schema refuse the uppercase max (`-32602`, 400 `invalid_query_params`) where the Rust spine accepts it, until they move to the twins. The `@fuzdev/fuz_schema` peer floor moves to `^0.5.4`. To migrate: install `@fuzdev/fuz_schema` 0.5.4 or later; replace any use of Zod's brand on a `Uuid` (`z.$brand<'Uuid'>`, `z.BRAND`) with `Branded<string, 'Uuid'>` from `@fuzdev/fuz_schema/schema.ts` or the `Uuid` type itself; `as Uuid` casts keep working.
