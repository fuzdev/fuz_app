break: `schema_to_surface` (`http/schema_helpers.ts`) no longer turns a JSON Schema conversion failure into `null`, which read as "takes no input" and dropped the schema from every suite reading the surface — the login, signup and bootstrap inputs, the account-status output, and every input or output holding a `Username` or `UsernameProvided` were `null` there, so `describe_data_exposure_tests` skipped those route outputs (and it never checked RPC or WS method outputs at all). It now takes a Zod or a `@fuzdev/fuz_schema` schema (`z.toJSONSchema` or fuz_schema's `to_json_schema`, by `is_schema`) and `{io?, source?, on_unrepresentable?}`: `generate_app_surface` writes inputs, params and query on the input side (what the server accepts, so a transform's bounds and pattern show) and outputs, error bodies and event params on the output side. A part JSON Schema can't say (an output-side transform, a `z.custom()`, a fuz_schema `check`) is left out or written as `{}` and recorded as an `info` diagnostic (category `schema`, `source` naming the route or method and side; not logged at startup). A schema with nothing describable (a `z.custom()`, a `z.date()` or a transform at the root, `z.unknown().transform(f)` included; `z.unknown()` and `z.any()` stay `{}`) or one an emitter refuses outright throws naming its source, so a server declaring one fails at assembly. `z.void()` stays `null`, as does a fuz_schema `literal(null)` beside `z.null()`. `is_null_schema` and `is_strict_object_schema` read fuz_schema schemas too (`literal(null)`, `object`, and an `object` refined in a `pipe` with no `transform` stage); `to_field_json_schema` and `detect_format` (`testing/schema_generators.ts`) take a fuz_schema field, and render either library with `unrepresentable: 'any'` (a `check` or `z.date()` is left out or `{}`, the bounds around it kept), so `to_field_json_schema` no longer returns `null`; a nullable bare type's `type: [type, 'null']` resolves to its one type. New export `extract_404_error_code` (`testing/adversarial_404.ts`), which reads either library with `unrepresentable: 'any'`, so a 404 schema with a transform beside `error` no longer drops its route from `describe_adversarial_404`. `events_to_surface` takes an optional diagnostics array. `describe_data_exposure_tests`' sensitive-field check (`password_hash`, `token_hash`) now covers every route, RPC method and WS method output and the params the server pushes over WS (a `remote_notification`'s payload, and the request of a `request_response` the backend initiates), each read on both sides — a field inside a transformed subtree shows only on the input side — and honors `skip_routes` (an RPC or WS method keyed `'/path method_name'`, pushed params `'/path method_name params'`); the admin-only-field check stays on route outputs. `assert_output_schemas_no_sensitive_fields` and `assert_non_admin_schemas_no_admin_fields` take the `AppSurfaceSpec` and an optional `skip_routes` instead of the `AppSurface`. A route, method or WS endpoint reads as admin-gated only when every role it admits is `admin` or `keeper` (an any-of `['admin', 'editor']` is not; `['keeper']` is), or it takes the daemon token. `collect_json_schema_property_names` also walks `prefixItems`, `patternProperties`, `$defs`/`definitions` values (a lazy or `.meta({id})` schema behind a `$ref`), `contains`, and `not`/`if`/`then`/`else`. To migrate: regenerate surface snapshots (inputs that were `null` are now described, and `diagnostics` gains the `info` rows), give any schema that now throws a JSON Schema form, or declare it `z.unknown()`, pass `surface_source` to the two data-exposure asserts, and add to `skip_routes` any output whose transform deliberately drops a blocklisted field.
