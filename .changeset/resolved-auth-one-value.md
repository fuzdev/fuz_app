break: the auth middleware leaves the request's credential on the Hono context as one value, `ResolvedAuth`, under `RESOLVED_AUTH_KEY` (`'resolved_auth'`), read with `get_resolved_auth(c)`. `ResolvedAuth` is a union on `credential_type`, each arm carrying only its own fields: `session` (`account_id`, `session_hash`, `credential_deadline`), `api_token` (`account_id`, `api_token_id`, `scope`, `credential_deadline`), `daemon_token` (`account_id`, `credential_deadline: null`) — `token_hash` is now `session_hash`, and the arms are exported as `ResolvedSessionAuth` / `ResolvedApiTokenAuth` / `ResolvedDaemonTokenAuth`. New accessors in `auth/resolved_auth.ts`: `resolved_auth_scope(auth)` (an API token's scope, `full` for a session or daemon token, `null` for anonymous), `resolved_auth_session_hash(auth)`, `resolved_auth_api_token_id(auth)`. Removed, with their `ContextVariableMap` entries: `ACCOUNT_ID_KEY` (`auth_account_id`) → `get_resolved_auth(c)?.account_id`; `CREDENTIAL_TYPE_KEY` (`credential_type`) → `get_resolved_auth(c)?.credential_type`; `TOKEN_SCOPE_KEY` (`token_scope`) → `resolved_auth_scope(get_resolved_auth(c))`; `AUTH_SESSION_TOKEN_HASH_KEY` (`auth_session_token_hash`, from `auth/request_context.ts`) → `resolved_auth_session_hash(get_resolved_auth(c))`; `AUTH_API_TOKEN_ID_KEY` (`auth_api_token_id`) → `resolved_auth_api_token_id(get_resolved_auth(c))`; `CREDENTIAL_DEADLINE_KEY` (`credential_deadline`) → `get_resolved_auth(c)?.credential_deadline`. A harness that set those keys sets `RESOLVED_AUTH_KEY` instead — `create_test_resolved_auth` (new, `testing/resolved_auth.ts`) builds the arm. `create_auth_middleware_specs` now returns `[origin, daemon_token?, session, request_context, bearer_auth]`: the credential legs run daemon token → session cookie → bearer, as the Rust spine resolves, the first that authenticates winning and the later legs skipping — so a cookie or bearer sent beside a valid daemon token is never looked up, and the bearer's `last_used_at` / `last_used_ip` no longer move; an attack-surface snapshot that lists the stack's names in order changes with it. The first credential leg composed (the daemon token's, else the session's) clears `RESOLVED_AUTH_KEY` on entry, so a layer mounted before the stack can't pre-set an identity the legs would skip past. `create_request_context_middleware(deps, options?)` takes `{session_context_key?, starts_chain?}` (new `RequestContextMiddlewareOptions`) in place of a positional `session_context_key`; `starts_chain` (default `true`) is the clear, and the stack passes `false` behind the daemon leg. `PerformActionInput` takes `auth: ResolvedAuth | null` in place of `account_id`, `credential_type`, `session_hash`, and `token_scope` (`ActionContext` keeps `credential_type` and `session_hash`). Testing: `create_fake_hono_context`'s `auth_session_id` and `api_token_id` and `WsConnectIdentity.api_token_id` take a string or nothing (not `null`); `create_fake_hono_context` ignores `auth_session_id` for a non-session credential (no session hash is set and none is left for the handler), and an `api_token` identity's `api_token_id` — on both helpers — defaults to a fresh uuid rather than `null`, so a harness that registers or closes connections by token id sees one; `create_bearer_auth_test_app`'s echo returns `{ok, resolved_auth, request_context_set}`.
