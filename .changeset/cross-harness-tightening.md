break: `xfail_until` requires the failure it expects, and the cross-backend harness's tests that couldn't fail now can

- break: `xfail_until(marker, name, fn)` takes an `XfailMarker` — `{tracking_id, reason, fails_with}` — in place of `(tracking_id, reason, name, fn)`. `fails_with` (`XfailMatcher`) is a `RegExp` tested against the thrown error's message or a predicate over the thrown value. The test passes only when the body throws a failure the matcher accepts; any other throw is red, naming the tracking id, with the original as `cause`; a matcher that throws is red, naming the tracking id and the body's failure, with the matcher's error as `cause`; and a body that passes is red with "gap closed — remove the marker". It registers a plain `test` (no longer `test.fails`), so a body that hits the test timeout is red where under `test.fails` it passed; the label is unchanged. `run_xfail(marker, fn)` and `xfail_matches(matcher, error)` are exported
- break: `ConformanceCaseXfail` is removed — `ConformanceCase.xfail` is an `XfailMarker`. `RpcParamsXfail` extends `XfailMarker`, and `transport_composition`'s `multi_actor.xfail` takes one, so every xfail entry states its `fails_with`. An `RpcParamsXfail` case's body throws the case's failure text whole (status and body), so a `fails_with` regex can match the answer, not only the case label; the conformance table's and the front-door table's failure messages carry the values they compare for the same reason
- break: renamed tests, for consumers keying `exclude_cases` on test-name paths: `cross-process websocket > anonymous upgrade is refused` is `cross-process websocket > anonymous upgrade is refused with 401`; `cross-process websocket > disallowed-origin upgrade is refused` is `cross-process websocket > disallowed-origin upgrade is refused with 403`; `per-account session cap parity > logging in N times evicts the oldest session (newest cookie resolves, first does not)` is `per-account session cap parity > logging in N times evicts the oldest session (the newest M resolve, the first does not)` (N the cap plus one, M the cap)
- testing: `ws_transport.ts`'s `create_ws_transport` rejects a refused upgrade with `WsUpgradeRefusedError`, carrying the refusal's `status` and `body`; its message reads `ws upgrade to <url> refused: Unexpected server response: NNN` where it read `ws upgrade to <url> failed: Unexpected server response: NNN`. The refused connection is closed once the body is read, and a body that hasn't ended within `WS_REFUSAL_BODY_TIMEOUT_MS` is cut off, rejecting with what arrived. `ws_endpoint.ts` adds `assert_ws_upgrade_refused(open, status)`, which the WS suites use in place of matching the status in the message
- testing: `integration_helpers.ts` adds `to_principal_transport(principal, fixture)` (and `PrincipalTransports`): the daemon-token principal goes cookie-free and without an `Origin`, the public principal cookie-free with the default `Origin`, and the session principals through the fixture's transport. The REST and RPC round trips and the data-exposure 2xx sweep send through it, so cross-process a daemon-gated call is no longer refused for its credential type behind the keeper's session cookie and passed as a refusal, and a public route or method is called anonymously on both legs (cross-process it was called as the keeper). An RPC success fixture's own `headers` go cookie-free with the default `Origin` and must carry a session `Cookie`
- testing: the REST and RPC round trips fail a 403 `credential_type_required` to any credentialed principal (`assert_route_authenticated`, `assert_rpc_authenticated`, over the new `is_credential_type_refusal`): the principal was picked because the auth admits its credential type, so that refusal means the credential never arrived as sent. A method or route admitting neither a session nor the daemon token (an API-token-only one) can't be driven by the round trip and goes in its skip list
- testing: `setup.ts` adds `match_testing_reset_seeds`, which `default_cross_process_setup` runs on every `_testing_reset` answer: seeded accounts are matched to the requested `extra_accounts` by username (lowercased) and `extra_actors` by name, never by position, and a missing, extra, or duplicated seed throws naming the backend
- testing: the integration suite's bearer probes (a valid bearer authenticates, another account's bearer still works, a bearer before and after a password change) and the data-exposure suite's unauthenticated sweep send cookie-free, so the keeper's session cookie can't answer for them; the bearer-with-`Referer` probe sends no `Origin`, so the `Referer` is what discards the bearer
- testing: `describe_cross_process_ws_tests` requires the anonymous upgrade refused 401 and a disallowed-origin upgrade carrying the keeper's valid session refused 403, with the refusal body's `error` `forbidden_origin` where the backend declares `capabilities.ws_refusal_body`; `describe_ws_role_gated_cross_tests` requires the re-upgrade after a revoke refused 403 by the refusal's status
- testing: `describe_cross_process_sse_tests` proves each close case's stream admitted (a broadcast `app_settings_update` frame read on it) before revoking; the data-frame case requires the frame to be the `session_revoke_all` row naming the account it revoked; the session-scoped close has a second session revoke the first, closing the named session's stream while the caller's stays open and receiving; the per-session cap case, given `rpc_path`, proves every survivor open by a frame written after the overflow; `login_path` is a new option for the session-scoped case's second login
- testing: `describe_session_cap_cross_tests` holds every one of the newest `max_sessions` sessions authenticating and the session list at exactly the cap, and its eviction case asserts the close reason and that a socket on a kept session stays open and dispatching; `describe_role_grant_offer_notification_ws_tests` asserts the permission-revoked close reason
- testing: `cross_backend/session_login.ts` adds `login_fresh_session(fixture, options)`, one more session of an account on a jar of its own
