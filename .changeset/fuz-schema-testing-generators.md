break: the testing generators and helpers read a `@fuzdev/fuz_schema` schema as well as a Zod one, and throw rather than yield no body or no cases: `generate_valid_body`, `generate_valid_object`, `generate_valid_object_with_field`, `generate_valid_value`, `generate_valid_string_param`, `resolve_valid_path`, `generate_input_test_cases`, `generate_params_test_cases`, `generate_query_test_cases`, `generate_rpc_params_test_cases` and `expected_invalid_reason` take a `ValidationSchema` (`generate_valid_body` and the adversarial cases through `zod_unwrap_to_object` crashed on a fuz_schema input, and a fuz_schema `regex` string field now generates a value it accepts); `assert_jsonrpc_success_response`, `rpc_call_for_spec`, `rpc_call_typed`, `expect_output`, `assert_response_matches_spec` and the conformance table validate through `parse_any`, `rpc_call_typed` and `expect_output` keeping their `<T>` and taking a fuz_schema `Schema<T>`. New in `testing/schema_generators.ts`: `to_object_schema_view` and `ObjectSchemaView`, `to_body_input`, and `GeneratedObject`; `zod.ts`'s `ZodFieldInfo` is renamed `SchemaFieldInfo`, the field info the generators read for either library. Breaking: `generate_valid_body` throws for an input that is neither an object, a void nor a null schema, where it returned `undefined`, and `generate_input_test_cases` throws for one, where it returned no cases (a void or null input gives `undefined` and no cases); `generate_valid_object`'s `result` is a `parse_any` result (`ok`, `value`, `issues`), not a Zod `safeParse` result; `format_zod_issues` is removed, the generators' errors rendering their issues with `format_issues`; every helper above throws on a schema of neither library. To migrate: rename `ZodFieldInfo` to `SchemaFieldInfo` (still from `zod.ts`); read `result.ok` and `result.issues` for `result.success` and `result.error.issues`; format issues with `format_issues` from `schema_issues.ts`; give an action or route whose input is no object schema an object input (a top-level union becomes an object with a `variant` or union field), or keep it out of the generated suites.
