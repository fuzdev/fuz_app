break: `resolve_valid_path` takes caller-supplied param values and throws on a `{re}` value its pattern refuses, and `assert_full_middleware_stack` honours carve-outs.

**Param values.** `resolve_valid_path(path, params_schema?, param_values?)` fills a param from `param_values` first, percent-encoded as the generated values are, so a `/` or `#` in it reaches the handler whole. A `:name{re}` param's value, supplied or generated, must now match its pattern — anchored `^(?:re)$` as Hono's RegExpRouter reads it (its TrieRouter leaves a top-level alternation ungrouped, `^re$`, which accepts more, so the check is the stricter of the two), over the value as Hono's router decodes it — or `resolve_valid_path` throws naming the route and the param and saying how to supply one, where such a route used to resolve to a path no route matches and 404; a supplied `''`, `.` or `..`, which the URL normalizes away, throws too, and so does a `param_values` entry naming no param of the path. No value is guessed from the pattern. The suites that resolve route paths take the values as `param_values: RouteParamValues` (new, in `testing/schema_generators.ts`: route key `'METHOD /path'` → param name → value): `describe_round_trip_validation`, `describe_data_exposure_tests`, `describe_adversarial_auth`, `describe_adversarial_input`, `describe_adversarial_404`, and `describe_standard_attack_surface_tests`, which forwards them to its three adversarial groups. `describe_standard_cross_process_tests` forwards its `param_values` to the round trip and data exposure, and `describe_spine_cross_suites` takes it as a `standard` override. `http/route_error_check.ts` exports `compile_route_param_pattern` and `decode_route_path`, the reading `find_route_spec` and `compile_route_path` share.

**Carve-outs.** `assert_full_middleware_stack`, the attack-surface suite's "full middleware stack on API routes" check, expects of each route the full list less each layer that carves it out: a layer whose `path` and one of whose `carve_outs` apply to the route (new `middleware_carves_out` in `http/schema_helpers.ts`, the half of `middleware_spec_applies` the surface and the route error map read), with no other layer of its name running there. So a consumer can carve a path under `/api/` out of a layer and keep the check. Everything else is held exactly as before: a route missing a layer no carve-out explains fails, and so does a carved-out route still listing it.

**To migrate:** a suite that resolves the path of a `{re}` route its fallback can't match now throws for it; pass a value for the param in that suite's `param_values`, or `skip_routes` the route.
