break: a route handler returns a result, `route_ok` / `route_fail` / `route_raw`, which `apply_route_specs` turns into the response, and a route spec is made by `define_route` (or `define_route_shape` + `attach_route_handler`), which checks the handler's results against the route. Every response of fuz_app's own routes is unchanged but one declared surface move (below).

**Results** (new `http/route_result.ts`, hono-free). `route_ok(value)` answers `value` as JSON at 200; `value` is never `undefined`, refused in the types. `route_fail(def, fields?)` answers `{error: def.code, ...fields}` at `def.status` with the headers the definition derives (`REST_RATE_LIMIT_EXCEEDED`'s `Retry-After`); `fields` is absent for a bare code, optional when every field is, required when any is. `route_raw(response)` answers a response built by hand as it is, at any status — an empty body, bytes, a stream, an SSE response, a JSON-RPC envelope; a `Response` typed as `c.json`'s return is refused, as a JSON answer of the route's own goes through `route_ok` or `route_fail`. A failure is plain data (`ok: false`, `status`, `code`, `body`, `def`), so domain code and shared helpers fail without the Hono context and a handler forwards one. Headers and cookies a handler sets on `c` before returning carry onto the response the framework builds. Types: `RouteOk`, `RouteFail`, `RouteRaw`, `RouteResult`, `RouteFailOf`, `RouteFailFields`, `RestErrorBodyInput`, `ReadonlyJson`.

**The typed link** (`http/route_spec.ts`). `RouteHandler` returns `RouteResult | Promise<RouteResult>`, and `apply_route_specs` builds the response from it (`to_route_response(c, result)`, exported, which throws on a `Response` or a malformed result). `define_route(spec)` checks the handler (`TypedRouteHandler`): `route_ok`'s value against the input side of `output`, made readonly at every depth (`ReadonlyJson`; `route_ok` keeps literals as written), and each `route_fail` against what the route allows — its `errors`, the 401 and auth 403s its `auth` derives and the 429 of its `rate_limit` (`RouteHandlerDerivedErrors`), and the catch layers' 500 `internal_error` and 503 `service_unavailable` (`RouteAlwaysErrors`) — read by what reaches the wire: a definition whose body an allowed one accepts at the same status and code passes, so the bare `REST_AUTHENTICATION_REQUIRED` is fine where `REST_AUTHENTICATION_REQUIRED_BOOTSTRAP` is declared, and the reverse. An `errors` list typed `Array<RestErrorDef>` is refused (`KnownRouteErrors`). `define_route_shape(shape)` keeps a route minus its handler with those types (`RouteShape`), and `attach_route_handler(shape, handler)` checks a handler against it. `RouteSpec` carries a phantom brand, in the types only, that only `define_route` and `attach_route_handler` mint: a spec literal no longer typechecks as a `RouteSpec`. A spread of a spec keeps the brand and is not checked again. At runtime the three return the spec, or the shape with its handler; `MiddlewareSpec` is unchanged.

**fuz_app's routes** are made this way: account (`/status`, `/verify`, `/login`, `/logout`, `/password`), signup, bootstrap, the audit stream, the db routes, health, ready, server status, `/api/surface`, both fact routes, and `create_rpc_endpoint`'s pair, whose envelopes are `route_raw` results with `c.json`'s bytes and content type. The shapes are `define_route_shape`s: `account_status_route_shape`, `bootstrap_route_shape`, and what `create_account_route_shapes` (now a readonly tuple), `create_signup_route_shape`, and `create_audit_log_route_shape` return (new `AuditStreamAuth`), where they were `Omit<RouteSpec, 'handler'>`.

**Removed:** `rate_limit_exceeded_response(c, retry_after)` (`rate_limiter.ts`) — `route_fail(REST_RATE_LIMIT_EXCEEDED, {retry_after})`, the same body and `Retry-After` header.

**The surface, one move.** `REST_DATABASE_CONNECTION_FAILED` declares the fields its body carries, `{connected: literal(false), type: string}`, the body `GET /health` and the Rust spine send on a failed check, so that route's 503 schema gains `connected` and `type`, both required. The body's keys are now written `error` first (`{"error":…,"connected":false,"type":…}`), as every failure's are.

**Testing.** `stub_handler()` returns a `route_raw` result; new `stub_route_spec(shape)` is a spec whose handler throws, for a surface described and never served (`create_rust_spine_consumer_surface_spec`'s spine routes). `describe_adversarial_404`'s stub handlers answer through `route_fail`.

**To migrate**, in order:

1. Wrap each route spec literal in `define_route({...})` (an array of them: each element), and drop a `: RouteSpec` annotation on a literal; type a factory's return `RouteSpec` or leave it inferred. A literal whose handler fails to typecheck reports only that, so the brand errors appear once the handlers are fixed and the first error count understates the work.
2. In each handler, `return c.json(value)` becomes `return route_ok(value)`; `return c.json({error: CODE}, status)` becomes `return route_fail(REST_X)` (with its fields: `route_fail(REST_X, {field})`), declaring `REST_X` in `errors` unless `auth` or `rate_limit` derives it; `rate_limit_exceeded_response(c, retry_after)` becomes `route_fail(REST_RATE_LIMIT_EXCEEDED, {retry_after})`; any other response (`c.body`, `c.text`, `new Response`, a stream, an SSE response) is wrapped in `route_raw(...)`, and a JSON body it carries is built with `c.body(JSON.stringify(x), status, {'Content-Type': 'application/json'})` if it is not the route's own answer. Leave `c.header` and `setCookie` calls where they are. A value typed `unknown` or an unconstrained generic narrows (or is cast to `{} | null`) before `route_ok`.
3. Fix what the types now find: an output a handler's value doesn't match, a failure the route doesn't declare (declare it, or answer what is declared), a required field left out of a failure.
4. A hono-free shape typed `Omit<RouteSpec, 'handler'>` (or `satisfies` it) becomes `define_route_shape({...})`, and `{...shape, handler}` becomes `attach_route_handler(shape, handler)`; a surface-only spec built from a shape takes `stub_route_spec(shape)`.
5. A test that calls `spec.handler(c, route)` and reads a `Response` reads it through `to_route_response(c, await spec.handler(c, route))`, as does a handler mounted on Hono directly (`app.post(path, async (c) => to_route_response(c, await spec.handler(c, route)))`).
6. Find the helpers that answer for a handler: one annotated `(c) => Response` that answers `c.json` (a `file_not_found(c)`), or an `enforce_*(): Response | null`. Wrapped as `route_raw(helper(c))` it typechecks, as its return type no longer says `c.json`, and the route's typed link is lost for that answer. Have it return a `RouteFailOf<typeof REST_X>` (`route_fail(REST_X, {message})`, with a definition that declares the fields it sends, such as `message`), and forward it from the handler (`if (failure) return failure`). A helper that answers text (`c.text`) stays a `route_raw`, outside the typed link.
7. A handler typed `any`, or in JS, that still returns a `Response`, or a result no factory made (a `{ok: true}` without `value`, a failure without its `status` or `def`, an `ok` other than `true`, `false`, or `'raw'`, a raw result without a response, `undefined` or `null`), answers 500 `internal_error` at runtime (`to_route_response` throws inside the dispatch), rolling back its transaction and discarding its `emit_after_commit` effects.
8. Regenerate any committed attack-surface snapshot that holds the `GET /health` of `create_db_route_specs` (`gro gen`), and review its 503.
